# Настройки окружения (.env)

## Новые настройки для разработки

### Время отправки сообщений (UTC)

Вы можете настроить время отправки утренних и вечерних сообщений через переменные окружения:

```env
# Время отправки утренних сообщений (UTC, формат HH:MM или HH)
MORNING_START=7:00   # Начало окна (по умолчанию: 07:00)
MORNING_END=8:00     # Конец окна (по умолчанию: 08:00)

# Время отправки вечерних сообщений (UTC, формат HH:MM или HH)
EVENING_START=21:00  # Начало окна (по умолчанию: 21:00)
EVENING_END=22:00    # Конец окна (по умолчанию: 22:00)
```

**Форматы времени:**
- `HH:MM` - полный формат (например, `20:30`, `21:35`)
- `HH` - только часы (автоматически добавляется `:00`, например, `7` → `7:00`)

**Примеры:**

Для тестирования с коротким интервалом:
```env
MORNING_START=20:30  # 20:30 UTC
MORNING_END=21:30    # 21:30 UTC
EVENING_START=21:30  # 21:30 UTC
EVENING_END=21:35    # 21:35 UTC (5 минут для быстрого тестирования)
```

Для тестирования в любое время дня:
```env
MORNING_START=14:00  # 14:00 UTC
MORNING_END=15:00    # 15:00 UTC
EVENING_START=16:00  # 16:00 UTC
EVENING_END=17:00    # 17:00 UTC
```

Для отправки только утром:
```env
MORNING_START=7:00
MORNING_END=8:00
EVENING_START=23:00  # После 23:00 (никогда не сработает)
EVENING_END=0:00     # До 00:00
```

**Обратная совместимость:**
Старый формат с только часами (например, `MORNING_START=7`) также поддерживается и автоматически преобразуется в `7:00`.

### Администратор

Для использования административных команд (например, `/reset_demo`):

```env
# Telegram ID администратора (можно получить через @userinfobot)
ADMIN_TG_ID=123456789
```

**Как получить свой Telegram ID:**
1. Откройте бота [@userinfobot](https://t.me/userinfobot) в Telegram
2. Отправьте команду `/start`
3. Скопируйте значение `Id` (это ваш `tg_id`)

## Административные команды

### `/reset_demo <tg_id_пользователя>`

Сбрасывает демо режим для указанного пользователя. **Если пользователь состоит в паре, демо сбрасывается для обоих пользователей пары автоматически.**

Доступна только администратору.

**Важно:**
- Команду может выполнить только администратор (проверяется автоматически по `ADMIN_TG_ID`)
- Аргумент `<tg_id_пользователя>` - это ID **пользователя**, для которого сбрасывается демо, **НЕ** ID администратора
- **Автоматически находит партнёра**: если пользователь состоит в паре, демо сбрасывается для обоих
- Если пользователь не состоит в паре, сбрасывается демо только для него одного

**Использование:**
```
/reset_demo 123456789
```

Где `123456789` - это Telegram ID пользователя (или любого из пары).

**Когда использовать:**
- При тестировании бота
- Когда нужно повторно протестировать onboarding для пары
- Для сброса ограничений демо режима

**Примеры:**

**Пример 1: Пользователь состоит в паре**
1. Пара: пользователь `111111111` и пользователь `222222222`
2. Администратор отправляет: `/reset_demo 111111111`
3. Бот автоматически находит партнёра (`222222222`)
4. Демо режим сбрасывается для **обоих**: `111111111` и `222222222`
5. Оба пользователя снова могут использовать демо режим

**Пример 2: Пользователь не состоит в паре**
1. Пользователь `333333333` не состоит в паре
2. Администратор отправляет: `/reset_demo 333333333`
3. Демо режим сбрасывается только для `333333333`

**Как узнать Telegram ID пользователя:**
- Попросите пользователя отправить `/start` боту [@userinfobot](https://t.me/userinfobot)
- Или используйте логи бота (там записывается `tg_id` при каждом сообщении)

## Загрузка картинок

Все картинки загружаются через основного бота (`TG_BOT_TOKEN`). Это гарантирует, что `file_id` будут работать корректно при отправке картинок пользователям, так как используется тот же бот.

**Важно:**
- Все картинки (утренние и вечерние) загружаются через основного бота
- `file_id` специфичны для каждого бота, поэтому важно использовать один и тот же бот для загрузки и отправки
- Скрипт загрузки автоматически увеличивает задержку при обнаружении ограничений Telegram API

## Примечания

- Все времена указаны в **UTC**
- Окна отправки работают так: если текущее время >= START и < END, то сообщения отправляются
- Worker проверяет время каждую минуту (cron: `minute="*"`) для точной проверки временных окон
- Изменения в `.env` требуют перезапуска бота и worker
- Поддерживается обратная совместимость: старый формат с только часами (например, `7`) автоматически преобразуется в `7:00`
