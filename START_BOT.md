# Как запустить бота

## Точка входа

**Точка входа бота**: `src/bot/main.py`

**Команда для запуска**:
```bash
python -m src.bot.main
```

## Что нужно перед запуском

### 1. Redis должен быть запущен

Бот использует Redis для хранения состояния (FSM storage). 

**Если используете Docker Compose:**
```bash
docker-compose up -d redis
```

**Если Redis установлен локально:**
- Убедитесь, что Redis запущен на порту 6379
- Windows: проверьте службы или запустите вручную

**Проверка Redis:**
```bash
# Если Redis в Docker
docker ps | grep redis

# Или попробуйте подключиться
redis-cli ping
# Должно ответить: PONG
```

### 2. Переменные окружения настроены

Убедитесь, что в `.env` заполнены:
- `TG_BOT_TOKEN` - токен бота
- `DATABASE_URL` - строка подключения к PostgreSQL
- `REDIS_URL` - строка подключения к Redis (по умолчанию `redis://localhost:6379/0`)

### 3. База данных готова

Миграции применены:
```bash
alembic upgrade head
```

## Запуск бота

### Вариант 1: Единая точка входа (рекомендуется)

Запускает и бота, и worker одновременно:

```bash
python run.py
```

### Вариант 2: Раздельный запуск (для отладки)

```bash
# Терминал 1: Bot
python -m src.bot.main

# Терминал 2: Worker (cron jobs)
python -m src.worker.main
```

Бот начнет работать в режиме **polling** (периодически опрашивает Telegram API на наличие новых сообщений).

### Что вы увидите:

```
{"event": "Starting Silent Couple Bot (Bot + Worker)", "logger": "run", "level": "info"}
{"event": "Worker process started (PID: ...)", "logger": "run", "level": "info"}
{"event": "Bot starting", "logger": "src.bot.main", "level": "info", "environment": "dev"}
```

Бот и worker готовы к работе! Теперь бот будет отвечать на команды, а worker будет отправлять сообщения по расписанию.

## Проверка работы

1. Откройте Telegram
2. Найдите вашего бота
3. Отправьте `/start`
4. Бот должен ответить

## Остановка бота

Нажмите `Ctrl+C` в терминале, где запущен бот.

## Режим работы

### Polling (по умолчанию)

Бот работает в режиме **polling** (по умолчанию):
- Бот периодически запрашивает новые сообщения у Telegram API
- Не требует настройки webhook
- Подходит для разработки и тестирования
- **Ограничение**: IP-адрес пользователя недоступен, автоматическое определение часового пояса не работает

### Webhook (для production)

Для production рекомендуется использовать **webhook**:
- Telegram отправляет обновления напрямую на ваш сервер
- **Преимущество**: доступен IP-адрес пользователя для автоматического определения часового пояса
- Требует домен с SSL сертификатом и настройку reverse proxy

Подробная инструкция: [WEBHOOK_SETUP.md](WEBHOOK_SETUP.md)

## Если бот не отвечает

1. **Проверьте логи** - должны быть сообщения об ошибках
2. **Проверьте токен** - убедитесь, что `TG_BOT_TOKEN` правильный
3. **Проверьте Redis** - должен быть запущен и доступен
4. **Проверьте БД** - должно быть подключение к PostgreSQL

## Для загрузки картинок

После запуска бота вы можете запустить загрузку картинок в **другом терминале**:

```bash
# Терминал 1: Бот (уже запущен)
python -m src.bot.main

# Терминал 2: Загрузка картинок
python scripts/load_images.py <your_chat_id>
```
