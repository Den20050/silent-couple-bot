# Руководство по логированию бота

## Обзор

Бот поддерживает логирование в файл с автоматической ротацией. Логи записываются как в консоль (PowerShell), так и в файл (если настроено).

## Настройка

### 1. Добавьте настройки в `.env` файл

```env
# Путь к файлу логов (относительно корня проекта)
# Оставьте пустым или не указывайте, чтобы отключить логирование в файл
LOG_FILE=logs/bot.log

# Максимальный размер файла лога перед ротацией (в байтах)
# По умолчанию: 10 МБ (10 * 1024 * 1024)
LOG_FILE_MAX_BYTES=10485760

# Количество резервных файлов логов для хранения
# По умолчанию: 5 (будет храниться bot.log, bot.log.1, bot.log.2, ..., bot.log.5)
LOG_FILE_BACKUP_COUNT=5
```

### 2. Запустите бота

После добавления настроек в `.env`, просто запустите бота как обычно:

```bash
python -m src.bot.main
```

или

```bash
python -m src.worker.main
```

## Как это работает

### Логирование в консоль

Логи **всегда** выводятся в консоль (PowerShell) в формате JSON от `structlog`. Это позволяет видеть логи в реальном времени при запуске бота.

### Логирование в файл

Если `LOG_FILE` указан в `.env`, логи также записываются в файл:

- **Расположение**: `logs/bot.log` (относительно корня проекта)
- **Формат**: JSON с временными метками
- **Ротация**: Автоматическая при достижении максимального размера
- **Резервные копии**: Хранятся `bot.log.1`, `bot.log.2`, ..., `bot.log.N`

### Пример структуры файлов логов

```
logs/
├── bot.log          # Текущий файл логов
├── bot.log.1        # Предыдущий файл (самый свежий)
├── bot.log.2        # Более старый файл
├── bot.log.3        # Еще более старый файл
└── bot.log.5        # Самый старый файл (после этого удаляется)
```

## Просмотр логов

### В PowerShell (консоль)

Логи выводятся в реальном времени при запуске бота. Вы можете перенаправить вывод в файл:

```powershell
python -m src.bot.main | Tee-Object -FilePath logs/console.log
```

### Просмотр файла логов

#### В PowerShell:

```powershell
# Просмотр последних 50 строк
Get-Content logs/bot.log -Tail 50

# Просмотр в реальном времени (как tail -f)
Get-Content logs/bot.log -Wait -Tail 20

# Поиск по логам
Select-String -Path logs/bot.log -Pattern "error"
```

#### В текстовом редакторе:

Откройте файл `logs/bot.log` в любом текстовом редакторе (VS Code, Notepad++, и т.д.).

## Формат логов

### Консоль (structlog JSON)

```json
{"event": "File logging enabled", "log_file": "C:\\Silent-Couple-Bot\\logs\\bot.log", "logger": "src.core.logger", "timestamp": "2025-12-29T12:34:56.789Z"}
```

### Файл (JSON с временными метками)

```json
{"time": "2025-12-29 12:34:56", "level": "INFO", "logger": "src.core.logger", "message": "{\"event\": \"File logging enabled\", \"log_file\": \"C:\\\\Silent-Couple-Bot\\\\logs\\\\bot.log\", \"logger\": \"src.core.logger\", \"timestamp\": \"2025-12-29T12:34:56.789Z\"}"}
```

## Уровни логирования

Настройте уровень логирования через переменную `LOG_LEVEL` в `.env`:

- `DEBUG` — детальная информация для отладки
- `INFO` — общая информация о работе бота (по умолчанию)
- `WARNING` — предупреждения
- `ERROR` — ошибки
- `CRITICAL` — критические ошибки

```env
LOG_LEVEL=DEBUG  # Для отладки
LOG_LEVEL=INFO   # Для продакшена (по умолчанию)
```

## Отключение логирования в файл

Чтобы отключить логирование в файл (оставить только консоль), установите пустое значение или не указывайте `LOG_FILE`:

```env
LOG_FILE=
```

или просто удалите строку из `.env`.

## Рекомендации

1. **Для разработки**: Используйте `LOG_LEVEL=DEBUG` и `LOG_FILE=logs/bot.log`
2. **Для продакшена**: Используйте `LOG_LEVEL=INFO` и настройте ротацию логов
3. **Размер файлов**: Установите `LOG_FILE_MAX_BYTES` в зависимости от объема логов (рекомендуется 10-50 МБ)
4. **Резервные копии**: Храните 5-10 резервных копий для анализа истории

## Устранение проблем

### Проблема: Файл логов не создается

**Решение:**
1. Проверьте, что `LOG_FILE` указан в `.env`
2. Проверьте права доступа к папке проекта
3. Убедитесь, что путь к файлу корректен

### Проблема: Логи не записываются в файл

**Решение:**
1. Проверьте логи в консоли — там должно быть сообщение "File logging enabled"
2. Если есть ошибка, она будет выведена в консоль
3. Убедитесь, что папка `logs/` существует и доступна для записи

### Проблема: Файл логов слишком большой

**Решение:**
1. Уменьшите `LOG_FILE_MAX_BYTES`
2. Уменьшите `LOG_FILE_BACKUP_COUNT`
3. Используйте более высокий уровень логирования (`INFO` вместо `DEBUG`)

## Примеры использования

### Просмотр последних ошибок

```powershell
Select-String -Path logs/bot.log -Pattern "\"level\":\"ERROR\"" | Select-Object -Last 10
```

### Поиск конкретного события

```powershell
Select-String -Path logs/bot.log -Pattern "pair created"
```

### Мониторинг в реальном времени

```powershell
Get-Content logs/bot.log -Wait -Tail 50 | Where-Object { $_ -match "ERROR" }
```
