# Миграция базы данных на сервер

Это руководство описывает процесс переноса базы данных с локального ПК на сервер.

## Текущая ситуация

- ✅ БД на сервере создана и доступна
- ✅ SSH туннель работает
- ❌ Миграции не применены на сервере
- ❌ Таблицы не созданы на сервере
- ❌ Данные не перенесены (если были на локальной БД)

## Шаг 1: Применение миграций на сервере

Примените миграции Alembic на сервере:

```bash
python scripts/run_migration.py
```

Это создаст все таблицы на сервере согласно моделям в коде.

**Проверка:**
```bash
python scripts/check_server_db_status.py
```

Должно показать:
- ✅ Migrations applied: True
- ✅ Total tables: > 0
- ✅ Список таблиц с количеством строк

## Шаг 2: Экспорт данных с локальной БД (если есть данные)

Если у вас есть данные в локальной БД, которые нужно перенести:

### 2.1. Запустите локальный PostgreSQL

```powershell
# Запустите службу PostgreSQL
Start-Service postgresql-x64-18
```

### 2.2. Экспортируйте данные

```bash
# Экспорт структуры и данных
pg_dump -h localhost -p 5433 -U bot_user -d silent_couple_bot -F c -f local_db_backup.dump

# Или в SQL формат
pg_dump -h localhost -p 5433 -U bot_user -d silent_couple_bot -f local_db_backup.sql
```

**Важно:** Замените `5433` на порт вашего локального PostgreSQL, если он другой.

## Шаг 3: Импорт данных на сервер

### Вариант А: Через SSH туннель (рекомендуется)

```bash
# Создайте SSH туннель для импорта
ssh -L 5433:localhost:5432 root@91.222.237.94

# В другом терминале импортируйте данные
pg_restore -h localhost -p 5433 -U bot_user -d silent_couple_bot local_db_backup.dump
```

### Вариант Б: Прямая передача через SSH

```bash
# Экспорт и передача через SSH одной командой
pg_dump -h localhost -p 5433 -U bot_user -d silent_couple_bot -F c | \
  ssh root@91.222.237.94 "pg_restore -h localhost -U bot_user -d silent_couple_bot"
```

### Вариант В: Загрузка файла на сервер

```bash
# Загрузите файл на сервер
scp local_db_backup.dump root@91.222.237.94:/tmp/

# Подключитесь к серверу
ssh root@91.222.237.94

# Импортируйте данные
pg_restore -h localhost -U bot_user -d silent_couple_bot /tmp/local_db_backup.dump
```

## Шаг 4: Проверка миграции

После импорта проверьте состояние БД на сервере:

```bash
python scripts/check_server_db_status.py
```

Должно показать:
- ✅ Все таблицы созданы
- ✅ Данные импортированы (если были)
- ✅ Миграции применены

## Если локальной БД нет или она пустая

Если у вас нет локальной БД или она пустая, просто примените миграции:

```bash
python scripts/run_migration.py
```

Это создаст пустую БД со структурой на сервере, готовую к работе.

## Важные замечания

1. **Порядок операций:**
   - Сначала примените миграции (создаст структуру)
   - Потом импортируйте данные (если есть)

2. **Конфликты:**
   - Если импортируете данные, которые уже есть в БД, могут быть конфликты
   - Используйте флаг `--clean` для очистки перед импортом (осторожно!)

3. **Бэкап:**
   - Перед импортом сделайте бэкап серверной БД:
   ```bash
   pg_dump -h localhost -U bot_user -d silent_couple_bot -F c -f server_backup_before_import.dump
   ```

4. **Проверка данных:**
   - После импорта проверьте количество строк в ключевых таблицах
   - Убедитесь, что данные корректны

3. ✅ Можно разрабатывать с разных ПК
4. ✅ Все данные синхронизированы на сервере
