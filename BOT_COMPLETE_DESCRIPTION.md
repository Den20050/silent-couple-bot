## Общее описание

**Silent Couple Bot** — Telegram-бот для пар, которые хотят ежедневно обмениваться простым знаком внимания: картинками «Доброе утро» и «Спокойной ночи», даже если не часто общаются.

### Ключевые особенности

- ✅ **Два режима работы**: для пар, которые часто общаются, и для тех, кто редко
- ✅ **Демо-период**: 7 дней бесплатного использования
- ✅ **Мультивалютная оплата**: поддержка 10 валют через Robokassa
- ✅ **Автоматические напоминания**: если партнёр не отвечает
- ✅ **Умные уведомления**: учитывают часовой пояс каждого пользователя
- ✅ **Micro-Surprise**: случайные тёплые подписи для разнообразия (только в Chat Mode)
- ✅ **GDPR compliance**: право на удаление всех данных

## Техническая архитектура

### Технологический стек

- **Bot Framework**: Python 3.11, aiogram 3.x, uvloop
- **Background Jobs**: arq (Redis-based async task queue)
- **Database**: PostgreSQL 15, SQLAlchemy 2.0 (async), asyncpg
- **Cache/Queue**: Redis 7
- **Migrations**: Alembic
- **Payment**: Robokassa (10 валют)
- **Web Server**: FastAPI (для webhook и Mini App)
- **Storage**: MinIO (S3-compatible) для картинок

### База данных

#### Таблицы

1. **users**
   - `id` (BIGINT, PK)
   - `tg_id` (BIGINT, UNIQUE) — Telegram ID пользователя
   - `username` (TEXT, NULLABLE) — Telegram username
   - `utc_offset` (INTEGER) — Часовой пояс (смещение от UTC в минутах)
   - `preferred_mode` (TEXT) — Выбранный режим: 'chat' или 'silent'
   - `consent` (BOOLEAN) — Согласие на обработку ПДн
   - `consent_dt` (TIMESTAMP) — Дата принятия согласия
   - `consent_ip` (TEXT) — IP адрес при принятии согласия
   - `payer_id` (BIGINT, FK) — ID пользователя, который оплатил подписку
   - `created_at`, `updated_at`

2. **pairs**
   - `id` (BIGINT, PK)
   - `uid_a` (BIGINT, FK) — ID первого пользователя (всегда меньше uid_b)
   - `uid_b` (BIGINT, FK) — ID второго пользователя
   - `mode` (TEXT) — Режим: 'chat' или 'silent'
   - `status` (TEXT) — Статус: 'trial', 'active', 'past_due'
   - `payer_id` (BIGINT, FK) — ID пользователя, который оплатил
   - `delivery_chat` (TEXT) — Где отправлять: 'bot_dm' или 'pair_dm'
   - `private_chat_id` (BIGINT, NULLABLE) — ID приватного чата пары (для Chat Mode)
   - `nickname_a`, `nickname_b` (TEXT) — Никнеймы для отображения
   - `created_at`, `updated_at`

3. **daily_state**
   - `pair_id` (BIGINT, FK, PK)
   - `day` (DATE, PK) — Дата
   - `morning_initiator` (BIGINT, FK) — ID инициатора утреннего пожелания
   - `morning_file_id` (TEXT) — File ID картинки утра
   - `morning_sent_at` (TIMESTAMP) — Когда отправлено утреннее пожелание
   - `morning_responded_at` (TIMESTAMP) — Когда получен ответ на утро
   - `evening_initiator` (BIGINT, FK) — ID инициатора вечернего пожелания
   - `evening_file_id` (TEXT) — File ID картинки вечера
   - `evening_sent_at` (TIMESTAMP) — Когда отправлено вечернее пожелание
   - `evening_responded_at` (TIMESTAMP) — Когда получен ответ на вечер
   - `last_surprise_at` (TIMESTAMP) — Последний Micro-Surprise (Chat Mode)
   - `created_at`

4. **subscriptions**
   - `id` (BIGINT, PK)
   - `pair_id` (BIGINT, FK)
   - `payer_id` (BIGINT, FK) — ID пользователя, который оплатил
   - `yoo_id` (TEXT, UNIQUE) — ID платежа от Robokassa
   - `status` (TEXT) — 'trial', 'active', 'past_due', 'cancelled', 'refunded'
   - `period_end` (DATE) — Дата окончания подписки
   - `is_lifetime` (BOOLEAN) — Бессрочная подписка
   - `last_past_due_notification_date` (DATE) — Последнее напоминание о просрочке
   - `created_at`, `updated_at`

5. **pics_pool**
   - `id` (BIGINT, PK)
   - `file_id` (TEXT, UNIQUE) — Telegram file_id картинки
   - `type` (TEXT) — 'morning' или 'evening'
   - `created_at`

6. **user_demo**
   - `user_a_id` (BIGINT, FK, PK)
   - `user_b_id` (BIGINT, FK, PK)
   - `created_at`
   - Защита от повторного использования демо-периода

7. **bot_messages**
   - `id` (BIGINT, PK)
   - `chat_id` (BIGINT) — Telegram chat_id
   - `message_id` (BIGINT) — Telegram message_id
   - `created_at` — Для очистки старых сообщений

### Фоновые задачи (Worker)

Worker использует **arq** (Redis-based async task queue) для выполнения cron-задач:

1. **morning_sender** (07:00-08:00 UTC)
   - Отправка запросов на утренние пожелания
   - Проверка временных окон пользователей
   - Выбор случайной картинки из пула

2. **evening_sender** (21:00-22:00 UTC)
   - Отправка запросов на вечерние пожелания
   - Аналогично утреннему

3. **cleanup_old_data** (03:00 UTC, ежедневно)
   - Удаление старых записей `daily_state` (старше 30 дней)
   - Удаление старых сообщений бота (старше 7 дней)

4. **dunning_notifications** (10:00 UTC, ежедневно)
   - Проверка просроченных подписок
   - Отправка напоминаний о необходимости оплаты

5. **send_recipient_reminder** (deferred job через arq)
   - Напоминание получателю, если он не ответил на пожелание
   - Планируется при отправке пожелания (см. `schedule_reminder_tasks`)

6. **send_initiator_warning** (deferred job через arq)
   - Предупреждение инициатору, если партнёр долго не отвечает
   - Поддерживает отмену (кнопка «❌ Отменить напоминания»)

8. **send_week_summary** (воскресенье, 20:00 UTC)
   - Отправка недельной статистики паре

9. **send_share_nudge** (14:00 UTC, ежедневно)
   - Напоминание поделиться ботом с другими

10. **send_renewal_reminders** (за 3 дня до окончания)
    - Напоминание о необходимости продления подписки

### Middleware

1. **DatabaseMiddleware** — Управление сессиями БД
2. **ErrorHandlerMiddleware** — Обработка исключений
3. **RateLimitMiddleware** — Ограничение частоты запросов
4. **TimezoneMiddleware** — Определение часового пояса пользователя
5. **IPExtractorMiddleware** — Извлечение IP для логирования согласия

## Роли пользователей

### 1. Обычный пользователь (User)

**Описание:** Основные пользователи бота — участники пар.

**Возможности:**
- Создание пары с партнёром
- Выбор режима общения (Chat Mode или Silent Mode)
- Ежедневный обмен картинками
- Просмотр статуса подписки
- Оплата подписки
- Настройки (часовой пояс, никнейм)
- Поделиться ботом с другими
- Обратная связь
- Удаление аккаунта (GDPR)

**Ограничения:**
- Один пользователь может быть в нескольких активных парах одновременно
- Демо-период можно использовать только один раз с каждым партнёром
- После окончания демо-периода требуется оплата подписки

**Команды:**
- `/start` — Начало работы, онбординг, перезапуск
- `/create_pair` — Создать новую пару
- `/subscription` — Просмотр статуса подписки
- `/pay` — Оплата подписки
- `/settings` — Настройки (часовой пояс, никнейм)
- `/share` — Поделиться ботом
- `/feedback` — Обратная связь
- `/bot_info` — Сведения о боте
- `/delete` — Удалить аккаунт и все данные

### 2. Администратор (Admin)

**Описание:** Пользователь с расширенными правами для управления ботом.

**Определение:** Администратор определяется через переменную окружения `ADMIN_TG_ID` в файле `.env`.

**Возможности:**

#### 📊 Статистика (`/admin_stats`)
- Общее количество пользователей
- Количество активных пар
- Количество активных подписок
- Статистика по режимам (Chat/Silent)
- Статистика по статусам подписок

#### 🔄 Сброс демо (`/admin_reset_demo`)
- Сброс демо-периода для конкретной пары
- Позволяет паре снова использовать 7 дней бесплатно

#### 🎁 Подарок подписки (`/admin_gift`)
- Выдача бесплатной подписки паре
- Выбор тарифа (1 месяц, 3 месяца, 6 месяцев, 1 год, навсегда)

#### 📢 Рассылка (`/admin_broadcast`)
- Отправка сообщений всем пользователям бота
- Поддержка HTML разметки

**Команды:**
- `/admin_stats` — Статистика бота
- `/admin_reset_demo` — Сброс демо-периода
- `/admin_gift` — Подарить подписку
- `/admin_broadcast` — Рассылка сообщений

## Пользовательские сценарии

### Сценарий 1: Первый запуск бота (новый пользователь)

**Цель:** Пользователь впервые запускает бота и создаёт пару с партнёром.

**Шаги:**

1. **Запуск бота**
   - Пользователь отправляет `/start`
   - Бот проверяет наличие согласия (`user.consent`)
   - Если согласия нет → показываются приветственные сообщения

2. **Приветственные сообщения (3 шага)**
   - **Шаг 1:** Описание бота и его функций
     - Кнопка: "Дальше ➡️"
   - **Шаг 2:** Описание режимов общения
     - Кнопка: "Дальше ➡️"
   - **Шаг 3:** Информация о подписках и оплате
     - Кнопка: "Принимаю ✅"

3. **Принятие политики конфиденциальности**
   - После "Принимаю ✅" показывается политика
   - Кнопка: "📄 Политика" (ссылка на внешний сайт)
   - Кнопка: "Принимаю ✅" (сохранение согласия)

4. **Выбор режима общения**
   - **💬 Часто общаемся** (Chat Mode)
     - Тёплые подписи, иногда милые сюрпризы
     - Для тех, кто и так много пишет
   - **💔 Редко** (Silent Mode)
     - Короткое «Со мной всё в порядке ❤️»
     - Для тех, кто практически не переписывается

5. **Получение ссылки-приглашения**
   - Бот генерирует ссылку: `https://t.me/bot?start=<tg_id>`
   - Пользователь отправляет ссылку партнёру

6. **Партнёр переходит по ссылке**
   - Партнёр отправляет `/start <tg_id>` боту
   - Проходит те же шаги (приветствие → политика → согласие)
   - Пара создаётся автоматически с режимом, выбранным первым пользователем

7. **Уведомление о создании пары**
   - Оба пользователя получают сообщение о создании пары
   - Указывается режим и длительность демо-периода (7 дней)

**Результат:**
- Создана запись в таблице `pairs`
- Создана подписка со статусом `trial` на 7 дней
- Оба пользователя могут начинать обмениваться пожеланиями

### Сценарий 2: Ежедневный обмен пожеланиями (утро)

**Цель:** Пользователи ежедневно обмениваются утренними пожеланиями.

**Алгоритм работы бота:**

1. **Cron задача (07:00-08:00 UTC)**
   - Worker запускает задачу `morning_sender`
   - Находит все активные пары (`status IN ('trial', 'active')`)
   - Для каждой пары проверяет временные окна (общие для пары + локальное время пользователей)

2. **Проверка временных окон**
   - У каждого пользователя есть `utc_offset` (часовой пояс)
   - Бот вычисляет локальное время пользователя
   - У пары есть единые окна (на пару):
     - `pairs.morning_window_start_hour` (по умолчанию 7)
     - `pairs.evening_window_start_hour` (по умолчанию 21)
     - `pairs.notification_window_owner_id` (кто установил окна первым)
   - Если владелец окна ещё не определён (`notification_window_owner_id IS NULL`) — используются дефолтные значения.
   - Если хотя бы один пользователь в своём временном окне → отправляется запрос обоим

3. **Отправка запроса**
   - Обоим пользователям отправляется сообщение с кнопкой "Отправить пожелание"
   - Первый, кто нажмёт кнопку, становится инициатором

4. **Пользователь нажимает кнопку**
   - Бот выбирает случайную картинку из пула (`pics_pool`, `type='morning'`)
   - Отправляет картинку партнёру
   - Сохраняет в `daily_state`:
     - `morning_initiator` = ID пользователя
     - `morning_file_id` = File ID картинки
     - `morning_sent_at` = текущее время

5. **Партнёр получает картинку**
   - Видит картинку с кнопкой "Отправить в ответ"
   - Нажимает кнопку → бот выбирает случайную картинку и отправляет инициатору
   - Сохраняет `morning_responded_at` в `daily_state`

6. **Напоминания (если партнёр не ответил)**
   - По `settings.reminder_hours` (по умолчанию 3/6/9 часов) → напоминания получателю
   - По `settings.warning_min_hours` и `settings.warning_interval_hours` → предупреждения инициатору

**Результат:**
- Оба пользователя обменялись утренними пожеланиями
- Цепочка завершена
- На следующий день процесс повторяется

### Сценарий 4: Оплата подписки

**Цель:** Пользователь оплачивает подписку после окончания демо-периода.

**Шаги:**

1. **Запуск оплаты**
   - Пользователь отправляет `/pay` или выбирает "💳 Оплатить" в меню
   - Бот проверяет наличие активной пары
   - Проверяет статус подписки

2. **Выбор тарифа**
   - Бот показывает список тарифов:
     - 1 месяц — 179 ₽
     - 3 месяца — 480 ₽ (экономия 57 ₽)
     - 6 месяцев — 860 ₽ (экономия 214 ₽)
     - 1 год — 1400 ₽ (экономия 748 ₽)
     - Навсегда — 2999 ₽

3. **Выбор валюты**
   - Поддерживается 10 валют: RUB, EUR, USD, UAH, BYN, KZT, AED, THB, TRY, CNY
   - Бот конвертирует цену по текущему курсу

4. **Создание платежа**
   - Бот генерирует платёжную ссылку через Robokassa
   - Параметры:
     - `MerchantLogin` — логин магазина
     - `OutSum` — сумма платежа
     - `InvId` — уникальный ID инвойса
     - `SignatureValue` — подпись (MD5)
     - `IsTest` — тестовый режим (если включен)

5. **Переход на страницу оплаты**
   - Пользователь переходит по ссылке
   - Оплачивает через Robokassa (карта, СБП, электронные кошельки)

6. **Webhook от Robokassa**
   - После успешной оплаты Robokassa отправляет POST запрос на `/webhook/robokassa`
   - Бот проверяет подпись платежа
   - Обновляет подписку:
     - `status` = `active`
     - `period_end` = продлевается на выбранный период
     - `is_lifetime` = `true` (если выбран тариф "Навсегда")
   - Обновляет статус пары: `status` = `active`
   - **Сбрасывает `daily_state`** для сегодняшнего дня
   - Отправляет обоим пользователям уведомление об активации подписки

**Результат:**
- Подписка активирована для обоих пользователей пары
- Пара может продолжать обмениваться пожеланиями

### Сценарий 5: Просроченная подписка

**Цель:** Обработка ситуации, когда подписка закончилась.

**Алгоритм:**

1. **Проверка просроченных подписок (10:00 UTC)**
   - Worker запускает задачу `dunning_notifications`
   - Находит все подписки с `period_end < сегодня` и `status IN ('trial', 'active')`
   - Обновляет статус пары: `status` = `past_due`

2. **Отправка напоминания**
   - Обоим пользователям отправляется сообщение о необходимости оплаты
   - Кнопка "💳 Оплатить" для быстрого перехода к оплате

3. **Повторные напоминания**
   - Напоминания отправляются не чаще раза в день
   - Используется `last_past_due_notification_date` для контроля

4. **После оплаты**
   - Подписка активируется
   - Статус пары меняется на `active`
   - Пара продолжает работу

### Сценарий 6: Создание второй пары

**Цель:** Пользователь хочет создать пару с другим партнёром.

**Шаги:**

1. **Запуск создания пары**
   - Пользователь отправляет `/create_pair`
   - Бот проверяет наличие согласия
   - Показывает выбор режима общения (как при первом запуске)

2. **Выбор режима**
   - Пользователь выбирает режим для новой пары
   - Режим может отличаться от режима первой пары

3. **Получение ссылки-приглашения**
   - Бот генерирует новую ссылку
   - Пользователь отправляет ссылку новому партнёру

4. **Создание пары**
   - Партнёр переходит по ссылке
   - Создаётся новая запись в таблице `pairs`
   - Создаётся новая подписка с демо-периодом

**Результат:**
- Пользователь может иметь несколько активных пар одновременно
- Каждая пара независима (свой режим, своя подписка)

### Сценарий 8: Удаление аккаунта (GDPR)

**Цель:** Пользователь хочет удалить все свои данные.

**Шаги:**

1. **Запуск удаления**
   - Пользователь отправляет `/delete`
   - Бот показывает предупреждение о необратимости действия

2. **Подтверждение**
   - Пользователь подтверждает удаление
   - Бот удаляет все данные:
     - Записи в таблице `users`
     - Все пары, где пользователь участвует (CASCADE)
     - Все подписки (CASCADE)
     - Все записи `daily_state` (CASCADE)
     - Все записи `user_demo` (CASCADE)

3. **Уведомление партнёру**
   - Если у пользователя была активная пара, партнёр получает уведомление
   - Пара становится неактивной

**Результат:**
- Все данные пользователя удалены из БД
- Пользователь может снова зарегистрироваться через `/start`

## Алгоритмы работы бота

### Алгоритм 1: Онбординг нового пользователя

```
1. Пользователь → /start
2. Проверка user.consent
   ├─ Нет → Показать приветственные сообщения (3 шага)
   │         → Показать политику конфиденциальности
   │         → Сохранить согласие (user.consent = true)
   └─ Да → Пропустить приветствие
3. Проверка user.preferred_mode
   ├─ Нет → Показать выбор режима общения
   │        → Сохранить режим (user.preferred_mode)
   └─ Да → Пропустить выбор
4. Проверка наличия активных пар
   ├─ Есть → Показать список пар
   └─ Нет → Показать ссылку-приглашение
```

### Алгоритм 2: Создание пары через invite link

```
1. Партнёр → /start <tg_id_приглашающего>
2. Проверка согласия партнёра
   ├─ Нет → Показать политику → Сохранить согласие
   └─ Да → Продолжить
3. Валидация создания пары:
   ├─ Проверка: пользователи не одинаковые
   ├─ Проверка: пара не существует
   ├─ Проверка: демо не использовано ранее
   └─ Проверка: приглашающий имеет режим
4. Создание пары:
   ├─ Создать запись в pairs (uid_a < uid_b)
   ├─ Создать подписку (trial, 7 дней)
   ├─ Отметить демо как использованное
   └─ Отправить уведомления обоим пользователям
```

### Алгоритм 3: Ежедневная отправка пожеланий

```
1. Cron задача (07:00 UTC для утра, 21:00 UTC для вечера)
2. Найти все активные пары (status IN ('trial', 'active'))
3. Для каждой пары:
   ├─ Получить пользователей пары
   ├─ Вычислить локальное время каждого пользователя
   ├─ Проверить временное окно (07:00-08:00 или 21:00-22:00)
   └─ Если хотя бы один в окне:
      ├─ Отправить запрос обоим пользователям
      ├─ Первый нажавший → инициатор
      ├─ Выбрать случайную картинку из пула
      ├─ Отправить картинку партнёру
      ├─ Сохранить в daily_state
      └─ Запланировать напоминания (через 2 и 4 часа)
```

### Алгоритм 4: Обработка платежа

```
1. Webhook от Robokassa → POST /webhook/robokassa
2. Проверка подписи платежа (MD5)
3. Поиск подписки по InvId
4. Проверка статуса платежа
5. Обновление подписки:
   ├─ status = 'active'
   ├─ period_end = продлить на выбранный период
   ├─ is_lifetime = true (если тариф "Навсегда")
   └─ Сбросить last_past_due_notification_date
6. Обновление статуса пары: status = 'active'
7. Сброс daily_state для сегодняшнего дня
8. Отправка уведомлений обоим пользователям
```

### Алгоритм 5: Проверка просроченных подписок

```
1. Cron задача (10:00 UTC, ежедневно)
2. Найти подписки:
   ├─ period_end < сегодня
   ├─ status IN ('trial', 'active')
   └─ is_lifetime = false
3. Для каждой подписки:
   ├─ Обновить status = 'past_due'
   ├─ Обновить status пары = 'past_due'
   ├─ Проверить last_past_due_notification_date
   └─ Если не отправлялось сегодня:
      ├─ Отправить напоминание обоим пользователям
      └─ Обновить last_past_due_notification_date
```

## Система подписок и платежей

### Статусы подписки

1. **`trial`** — Пробный период (7 дней)
   - Автоматически создаётся при создании пары
   - Бесплатный
   - Можно использовать только один раз с каждым партнёром

2. **`active`** — Активная подписка (оплачена)
   - Создаётся после успешной оплаты
   - Действует до `period_end`
   - Может быть продлена при следующей оплате

3. **`past_due`** — Подписка просрочена
   - Автоматически устанавливается после окончания периода
   - Пара не может обмениваться пожеланиями
   - Требуется оплата для продолжения

4. **`cancelled`** — Подписка отменена
   - Устанавливается администратором
   - Пара не может обмениваться пожеланиями

5. **`refunded`** — Подписка возвращена
   - Для будущего использования
   - Пара не может обмениваться пожеланиями

### Платежная система: Robokassa

**Интеграция:**
- Генерация платёжных ссылок с подписью (MD5)
- Обработка webhook'ов от Robokassa
- Проверка подписи платежей
- Поддержка тестового режима

**Параметры платежа:**
- `MerchantLogin` — логин магазина
- `OutSum` — сумма платежа (форматируется без лишних нулей)
- `InvId` — уникальный ID инвойса (числовой, до 10 цифр)
- `SignatureValue` — подпись (MD5 хеш)
- `IsTest` — тестовый режим (1 для теста, 0 для продакшена)
- `OutSumCurrency` — валюта (только для не-RUB валют)

## Ежедневный обмен пожеланиями

### Временные окна

Каждый пользователь имеет свой часовой пояс (`utc_offset`). Бот вычисляет локальное время пользователя и отправляет запросы в определённые временные окна **на пару** (общие для обоих партнёров):

- **Утреннее окно:** `pairs.morning_window_start_hour:00` → `+1 час` (локальное время каждого пользователя)
- **Вечернее окно:** `pairs.evening_window_start_hour:00` → `+1 час` (локальное время каждого пользователя)

Если хотя бы один пользователь пары находится в своём временном окне, запрос отправляется обоим.

**Владелец окна:** первый партнёр, который выбрал окно, становится владельцем (`pairs.notification_window_owner_id`). Второй партнёр получает уведомление и больше не может менять окна через UI — изменение делает только владелец.

### Режимы общения

#### Silent Mode (💔 Редко)

- Короткое сообщение: «Со мной всё в порядке ❤️»
- Никаких дополнительных текстов
- Для тех, кто практически не переписывается

#### Chat Mode (💬 Часто общаемся)

- Тёплые подписи к картинкам
- Иногда милые сюрпризы (Micro-Surprise)
- Для тех, кто и так много пишет, но хочет ежедневный ритуал

**Micro-Surprise:**
- Случайные тёплые подписи (только в Chat Mode)
- Отправляются не чаще раза в день
- Используется `last_surprise_at` для контроля

### Напоминания

1. **Напоминания получателю**
   - Если партнёр не ответил, получатель получает напоминания по `settings.reminder_hours` (по умолчанию `3,6,9` часов).

2. **Предупреждения инициатору**
   - Если ответа всё ещё нет, инициатор получает предупреждения начиная с `settings.warning_min_hours` (по умолчанию `10` часов) и далее раз в `settings.warning_interval_hours` (по умолчанию `6` часов), до истечения `settings.warning_ttl_days` (по умолчанию `7` дней).
   - Инициатор может отключить предупреждения кнопкой «❌ Отменить напоминания» — флаг хранится в Redis на весь горизонт предупреждений.

3. **Идемпотентность и защита от дублей**
   - Напоминания и предупреждения защищены Redis-ключами, чтобы не отправляться повторно при ретраях/рестартах воркера.

Позволяет администратору выдать бесплатную подписку паре:
1. Администратор отправляет `/admin_gift`

4. Бот создаёт подписку с выбранным тарифом
5. Обоим пользователям отправляется уведомление

### Рассылка (`/admin_broadcast`)

Позволяет администратору отправить сообщение всем пользователям:
1. Администратор отправляет `/admin_broadcast`
2. Вводит текст сообщения (поддерживается HTML)
3. Бот отправляет сообщение всем пользователям из таблицы `users`
4. Показывается прогресс отправки

## Анти-спам и «только одна актуальная кнопка»

Цель: убрать “ощущение спама” и путаницу из-за множества кнопок в старых сообщениях.

### 1) Только одно активное интерактивное сообщение

В Redis хранится “активное” сообщение для каждого пользователя и типа действия:

- **PROMPT**: запрос “Кому отправить утреннее/вечернее пожелание”
- **REMINDER**: напоминание “Тебя ждут … / Ответь картинкой”

Когда появляется новое интерактивное сообщение, бот **best-effort** снимает кнопки со старого (через `remove_reply_markup`).  
Приоритет: **PROMPT** также отключает кнопки у **REMINDER**, чтобы пользователь не отвечал “не туда”.

### 2) Защита от кликов по старым кнопкам

Callback handlers проверяют, что нажатие происходит на активном сообщении.  
Если сообщение устарело — показывается алерт “сообщение устарело”, а кнопки у этого сообщения снимаются.

### 3) Снятие кнопки “Ответить” с картинки-пожелания после напоминания

Пожелание приходит как **картинка с кнопкой ответа**. Когда приходит напоминание “Тебя ждут…”, бот дополнительно снимает кнопки у исходной картинки, чтобы в чате оставалась **ровно одна** актуальная кнопка (в последнем напоминании).

Технически:
- при отправке картинки сохраняется `message_id` в Redis: `wish_photo_message_id:{tg_id}:{pair_id}:{pic_type}:{day}`
- при отправке напоминания воркер делает `remove_reply_markup` по этому `message_id`
