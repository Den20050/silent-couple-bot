# Алгоритм работы бота Silent Couple Bot

## Роли пользователей

### Технические роли (в базе данных)

- **uid_a** и **uid_b** — технические идентификаторы пользователей в паре
  - Используются только для хранения связи между двумя пользователями
  - `uid_a < uid_b` (для предотвращения дубликатов)
  - **НЕ имеют смысла "инициатор" или "получатель"**

### Роли в ежедневном взаимодействии

- **Инициатор (Initiator)** — пользователь, который первым нажал кнопку "Отправить" в течение дня
  - Определяется полем `daily_state.morning_initiator` или `daily_state.evening_initiator`
  - Может быть любым из двух пользователей пары
  - Меняется каждый день в зависимости от того, кто первым нажал

- **Получатель (Recipient)** — второй пользователь в паре, который должен ответить на пожелание
  - Определяется как противоположный инициатору пользователь
  - Получает картинку от инициатора
  - Должен ответить, нажав кнопку "Отправить в ответ"

### Роли в системе управления

- **Администратор (Admin)** — пользователь с расширенными правами для управления ботом
  - Определяется через переменную окружения `ADMIN_TG_ID`
  - Имеет доступ к командам `/admin` (статистика) и `/reset_demo` (сброс демо режима)
  - Подробнее см. раздел "Администратор (Admin)" ниже

## Алгоритм работы бота

### 1. Создание пары (Onboarding)

**Пользователь А (Inviter — приглашающий):**
1. Отправляет `/start`
2. Принимает политику конфиденциальности
3. Выбирает режим общения:
   - **💬 Часто общаемся** → Chat Mode
   - **💔 Редко** → Silent Mode
4. Получает ссылку-приглашение
5. Отправляет ссылку партнёру

**Пользователь В (Invited — приглашённый):**
1. Переходит по ссылке-приглашению (`/start <tg_id_пользователя_А>`)
2. Принимает политику конфиденциальности
3. Пара создаётся автоматически с режимом, выбранным Пользователем А
4. Оба пользователя получают уведомление о создании пары

**Результат:**
- Создаётся запись в таблице `pairs`:
  - `uid_a` = ID пользователя А (приглашающего)
  - `uid_b` = ID пользователя В (приглашённого)
  - `mode` = режим, выбранный пользователем А
  - `status` = 'trial' (демо режим)
- Создаётся подписка с демо-периодом 7 дней:
  - `status` = 'trial'
  - `period_end` = сегодня + 7 дней
- Оба пользователя помечаются в таблице `user_demo` (защита от повторного использования демо)

### 2. Ежедневный обмен картинками

#### 2.1. Утренние картинки (07:30-08:30 UTC)

**Шаг 1: Бот отправляет запросы обоим пользователям**

В указанное время бот отправляет обоим пользователям пары сообщение с кнопкой:

**Silent Mode:**
```
"Хотите отправить пожелание с \"Добрым утром\"?"
[Кнопка: "Отправить в ответ"]
```

**Chat Mode:**
```
"Утро! Отправьте доброе пожелание в ответ:"
[Кнопка: "Отправить в ответ"]
```

**Шаг 2: Первый пользователь нажимает кнопку (становится Инициатором)**

- Пользователь нажимает кнопку "Отправить в ответ"
- Бот атомарно устанавливает `daily_state.morning_initiator = user_id`
- Если другой пользователь уже нажал — показывается сообщение: "Ваш партнёр уже отправил пожелание"
- Инициатору показывается: "✅ Вы отправили пожелание"

**Шаг 3: Бот отправляет картинку Получателю**

- Получатель получает картинку с подписью:
  - **Silent Mode:** "Со мной всё в порядке ❤️"
  - **Chat Mode:** "Доброе утро, солнце ☀️" (или Micro-Surprise подпись, см. раздел 2.3)
- К картинке прикреплена кнопка: "Отправить в ответ"

**Шаг 4: Получатель отвечает (становится Инициатором для ответа)**

- Получатель нажимает кнопку "Отправить в ответ"
- Бот проверяет:
  - ✅ Пользователь действительно является получателем (не инициатором)
  - ✅ Ответ ещё не был отправлен (`morning_responded_at IS NULL`)
- Бот отправляет новую случайную картинку Инициатору
- Устанавливается `daily_state.morning_responded_at = NOW()`
- Сообщение Получателя редактируется: "✅ Вы ответили на пожелание"

**Результат:**
- Инициатор получил картинку от Получателя
- Обмен завершён
- Оба пользователя подтвердили, что всё в порядке

#### 2.3. Micro-Surprise (только для Chat Mode)

**Назначение:** Разнообразить общение в Chat Mode, добавляя случайные тёплые подписи к картинкам.

**Как работает:**

1. **Частота:** Примерно раз в 3-4 дня (случайно, без привязки ко времени суток)
2. **Механизм:**
   - При формировании сообщения генерируется случайное число от 1 до 4
   - Если выпадает "1" **И** с момента последнего сюрприза прошло ≥ 72 часов → используется случайная подпись из массива сюрпризов
   - Иначе используется стандартная подпись
3. **Хранение:** В `daily_state.last_surprise_at` сохраняется время последнего сюрприза

**Подписи для утренних картинок:**
- "Доброе утро ☀️… а теперь иди целуй меня"
- "Твоё утро начинается со мня — и это прекрасно"
- "Доброе утро, солнце ☀️"

**Подписи для вечерних картинок:**
- "Засыпай — я рядом, даже если молчу"
- "Спокойной ночи… и не думай о ком-то другом ❤️"
- "Спокойной ночи, мой человек 🌙"

**Технические детали:**
- Реализовано в функции `get_caption_with_surprise()` в `src/bot/handlers/callbacks.py`
- Используется в `handle_request_morning`, `handle_tap_morning`, `handle_request_evening`, `handle_tap_evening`
- После использования сюрприза обновляется `daily_state.last_surprise_at` через `update_last_surprise_at()`
- Минимальный интервал между сюрпризами: 72 часа (3 дня)

### 3. Система напоминаний

#### 3.1. Напоминания Получателю (2, 4, 6 часов после отправки)

Если Получатель не ответил в течение указанного времени:

**Через 2, 4, 6 часов:**

**Silent Mode:**
```
"Ваш близкий ждёт подтверждения что у вас всё хорошо."
```

**Chat Mode:**
```
"Ваш близкий ждёт подтверждения что у вас всё хорошо."
```

**Отправляется:** Получателю (тому, кто должен ответить)

#### 3.2. Предупреждения Инициатору (10 часов и далее каждый час)

Если Получатель не ответил в течение 10+ часов:

**Через 10+ часов (каждый час до 24 часов):**

**Silent Mode:**
```
"⚠️ @username не отвечает, воспользуйтесь другим способом узнать, всё ли у него в порядке."
[Кнопка: "❌ Отменить напоминания"]
```

**Chat Mode:**
```
"⚠️ @username не отвечает, воспользуйтесь другим способом узнать, всё ли у него в порядке."
[Кнопка: "❌ Отменить напоминания"]
```

**Отправляется:** Инициатору (тому, кто отправил пожелание)

**Отмена напоминаний:**
- Инициатор может нажать кнопку "❌ Отменить напоминания"
- Флаг сохраняется в Redis: `initiator_warning_cancelled:{pair_id}:{day}:{pic_type}`
- Дальнейшие предупреждения не отправляются

### 4. Режимы работы

Бот поддерживает два режима общения, которые выбираются при создании пары:

#### Silent Mode (💔 Редко общаемся)

**Назначение:** Для пар, которые редко общаются. Утром и вечером бот предлагает первым нажавшему отправить «маяк» — короткую картинку. Второй человек получит её в личку и может ответить своей. Никаких слов, никакого чата: одно нажатие = «я жив, всё в порядке».

**Как работает:**

1. **Выбор режима:**
   - При создании пары пользователь выбирает "💔 Редко"
   - Режим сохраняется в `pair.mode = 'silent'`

2. **Ежедневный обмен:**
   - **07:30-08:30 UTC (утро):** Бот отправляет обоим пользователям в **личный чат с ботом**:
     ```
     "Хотите отправить пожелание с «Добрым утром»?"
     [Кнопка: "Отправить в ответ"]
     ```
   - Подпись картинки: *"Со мной всё в порядке ❤️"*
   - **21:30-22:30 UTC (вечер):** Аналогично для вечерних картинок:
     ```
     "Хотите отправить пожелание с «Спокойной ночи»?"
     [Кнопка: "Отправить в ответ"]
     ```
   - Подпись картинки: *"Я в безопасности, спокойной ночи ❤️"*

3. **Процесс отправки:**
   - Пользователь нажимает кнопку "Отправить в ответ" в своём личном чате с ботом
   - Бот атомарно устанавливает инициатора
   - Бот отправляет картинку **партнёру в его личный чат с ботом**
   - Партнёр видит картинку с кнопкой "Отправить в ответ"
   - Партнёр нажимает кнопку → Бот отправляет ответную картинку инициатору

4. **Особенности:**
   - ✅ Полная изоляция: пользователи не видят друг друга напрямую
   - ✅ Все сообщения идут через бота
   - ✅ Подходит для пар, которые хотят минимального контакта
   - ✅ Система напоминаний работает полностью
   - ✅ Картинки не сохраняются в галерее
   - ✅ Напоминания мягкие, личное пространство не тронуто

**Технические детали:**
- В `morning_sender` проверяется: `if pair.mode == "chat":` → используется Chat Mode, иначе Silent Mode
- Обработчики: `handle_request_morning` и `handle_tap_morning` в `src/bot/handlers/callbacks.py`
- Картинки отправляются через `send_photo_with_retry` напрямую в `tg_id` партнёра
- Разница между режимами только в тексте сообщений и кнопок

#### Chat Mode (💬 Часто общаемся)

**Назначение:** Для пар, которые часто общаются. Тот же механизм, что и в Silent Mode, но тексты и подписи звучат как «доброе утро, солнце» и «спокойной ночи, мой человек». Картинки приходят в личку, их можно переслать партнёру или просто сохранить себе. Ни одного лишнего сообщения — только лучик внимания два раза в день.

**Как работает:**

1. **Выбор режима:**
   - При создании пары пользователь выбирает "💬 Часто общаемся"
   - Режим сохраняется в `pair.mode = 'chat'`
   - **Никаких дополнительных действий не требуется!** Бот работает сразу после создания пары

2. **Ежедневный обмен:**
   - **07:30-08:30 UTC (утро):** Бот отправляет обоим пользователям в **личный чат с ботом**:
     ```
     "Утро! Отправьте доброе пожелание в ответ:"
     [Кнопка: "Отправить в ответ"]
     ```
   - Подпись картинки: *"Доброе утро, солнце ☀️"* (или случайная Micro-Surprise подпись раз в 3-4 дня)
   - Подпись ответа: *"Тебе ответили ❤️"*
   - **21:30-22:30 UTC (вечер):** Аналогично для вечерних картинок:
     ```
     "Вечер! Отправьте пожелание на ночь:"
     [Кнопка: "Отправить в ответ"]
     ```
   - Подпись картинки: *"Спокойной ночи, мой человек 🌙"* (или случайная Micro-Surprise подпись раз в 3-4 дня)
   - Подпись ответа: *"Тебе ответили ❤️"*

3. **Процесс отправки:**
   - Пользователь нажимает кнопку "Отправить пожелание" в своём личном чате с ботом
   - Бот атомарно устанавливает инициатора
   - Бот отправляет картинку **партнёру напрямую в его личный чат с ботом**
   - Партнёр видит картинку с кнопкой "Ответить"
   - Партнёр нажимает кнопку → Бот отправляет ответную картинку инициатору

4. **Особенности:**
   - ✅ **Не требует добавления бота в общий чат** — полностью приватно
   - ✅ Картинки отправляются напрямую в личный чат партнёра
   - ✅ Более естественный UX по сравнению с Silent Mode (другая формулировка текста)
   - ✅ Система напоминаний работает полностью
   - ✅ Подходит для пар, которые часто общаются, но ценят приватность
   - ✅ Micro-Surprise: случайные тёплые подписи раз в 3-4 дня для разнообразия
   - ✅ Картинки можно переслать партнёру или сохранить себе

**Технические детали:**
- В `morning_sender` проверяется: `if pair.mode == "chat":` → используется Chat Mode
- Обработчики: `handle_request_morning` и `handle_tap_morning` в `src/bot/handlers/callbacks.py`
- Картинки отправляются через `send_photo_with_retry` напрямую в `tg_id` партнёра

**Важно:**
- Команда `/link` больше не требуется и показывает информационное сообщение
- Chat Mode теперь работает аналогично Silent Mode, но с другим текстом и UX

### 5. Подписка и демо режим

#### 5.1. Демо период (7 дней)

**При создании пары:**
- Автоматически создаётся подписка со статусом `trial`
- Период действия: 7 дней с момента создания
- Статус пары: `trial`
- Оба пользователя получают доступ ко всем функциям бота

**Во время демо периода:**
- Бот работает в полном режиме
- Утренние и вечерние сообщения отправляются ежедневно
- Пользователи могут обмениваться картинками
- Все функции доступны без ограничений

#### 5.2. Окончание демо периода

**Процесс обнаружения просрочки:**
- Ежедневно в **10:00 UTC** запускается задача `dunning_notifications`
- Находятся все подписки, где `period_end < today` и `status IN ('trial', 'active')`
- Статус пары автоматически меняется на `past_due`

**Что происходит после перехода в `past_due`:**
1. **Утренние и вечерние сообщения:**
   - Пары со статусом `past_due` **НЕ получают** обычные утренние/вечерние запросы
   - Вместо этого они получают уведомление:
     ```
     "Демо режим закончился. Для продолжения работы бота выберите тариф и оплатите подписку."
     [Кнопка: "Выбрать тариф"]
     ```
   - Уведомление отправляется утром (07:30-08:30 UTC) и вечером (21:30-22:30 UTC)

2. **Блокировка функций:**
   - Все обработчики callbacks проверяют статус пары
   - При попытке использовать старые кнопки показывается:
     ```
     "⏳ Подписка просрочена. Оплатите для продолжения использования."
     ```
   - Отправка картинок блокируется до оплаты

3. **Команда `/pay`:**
   - Доступна для просроченных подписок
   - Показывает список тарифов для оплаты
   - После успешной оплаты статус меняется на `active`

#### 5.3. Восстановление после оплаты

**При успешной оплате:**
1. Webhook от YooKassa обрабатывает платеж
2. Подписка обновляется:
   - `status` = 'active'
   - `period_end` продлевается на выбранный период
   - `yoo_id` сохраняется
3. Статус пары меняется на `active`
4. Обоим пользователям отправляется уведомление:
   ```
   "✅ Подписка активна до {дата}"
   ```
5. Работа бота возобновляется в полном режиме

#### 5.4. Команда `/subscription`

**Показывает текущий статус подписки:**
- **trial:** "Демо режим активен, остаток {N} дней"
- **active:** "Подписка активна, остаток {N} дней"
- **past_due:** "⏳ Подписка просрочена. Оплатите для продолжения использования."

### 6. Система очистки сообщений

#### 6.1. Автоматическое удаление старых сообщений

**Назначение:** Поддерживать чат бота в чистоте, удаляя старые сообщения.

**Как работает:**
1. **Сохранение message_id:**
   - При отправке каждого сообщения через `send_message_with_retry()` или `send_photo_with_retry()` сохраняется `message_id` в таблице `bot_messages`
   - Сохраняются: `chat_id`, `message_id`, `sent_at`

2. **Автоматическая очистка:**
   - Ежечасно в **:30 минут** запускается задача `cleanup_old_messages`
   - Находятся все сообщения старше 48 часов (`sent_at < NOW() - 48 hours`)
   - Сообщения удаляются через Telegram API
   - Записи из БД удаляются только для успешно удалённых сообщений

3. **Обработка ошибок:**
   - Если сообщение уже удалено пользователем — считается успешным удалением
   - Ошибки удаления обрабатываются без логирования (тихая обработка)

**Технические детали:**
- Реализовано в `src/worker/jobs.py:cleanup_old_messages()`
- Использует репозиторий `BotMessagesRepository`
- Функция `delete_message_with_retry()` обрабатывает retry-логику и ошибки

### 7. Важные моменты

#### Атомарность операций

**Что означает "только один пользователь может стать инициатором в течение дня":**

**Важно:** Утренние и вечерние обмены **независимы друг от друга**. Это означает:
- Утром может быть один инициатор (например, Пользователь А)
- Вечером может быть другой инициатор (например, Пользователь В)
- Или один и тот же пользователь может быть инициатором и утром, и вечером

**Как это работает для каждого обмена (утреннего или вечернего):**

Когда бот отправляет утренний **или** вечерний запрос обоим пользователям пары, оба видят кнопку "Отправить в ответ". Однако:

- **Только первый**, кто нажмёт кнопку в рамках этого конкретного обмена (утреннего или вечернего), становится **Инициатором** и отправляет пожелание партнёру
- **Второй** пользователь, который попытается нажать кнопку после этого, увидит сообщение: *"Ваш партнёр уже отправил пожелание"*
- Это предотвращает ситуацию, когда оба пользователя одновременно отправляют пожелания друг другу в рамках одного обмена

**Пример:**
- **Утро:** Пользователь А нажимает первым → становится утренним инициатором → Пользователь В получает картинку
- **Вечер:** Пользователь В нажимает первым → становится вечерним инициатором → Пользователь А получает картинку

**Техническая реализация:**
- Установка инициатора происходит атомарно через `set_morning_initiator` / `set_evening_initiator`
- В БД хранятся отдельные поля: `morning_initiator` и `evening_initiator`
- Используется `SELECT FOR UPDATE` для предотвращения гонок (race conditions)
- Если оба пользователя нажимают кнопку одновременно, только один успешно становится инициатором для этого конкретного обмена

#### Отслеживание ответов

- `morning_sent_at` / `evening_sent_at` — когда была отправлена картинка
- `morning_responded_at` / `evening_responded_at` — когда был получен ответ
- Используется для системы напоминаний

#### Защита от дубликатов

- Redis используется для отслеживания отправленных напоминаний
- Ключи: `reminder_recipient:{pair_id}:{day}:{pic_type}:{hours}`
- Ключи: `initiator_warning:{pair_id}:{day}:{pic_type}:{hours}`
- Ключи: `initiator_warning_cancelled:{pair_id}:{day}:{pic_type}`

### 4. Итог недели

**Назначение:** Подвести итоги недели и показать пользователям статистику их взаимодействия.

**Как работает:**

1. **Расписание:** Отправляется каждый день в **00:00 UTC** (начало нового дня)
2. **Условия отправки:**
   - Отправляется только если в последние 7 дней были обмены картинками
   - Отправляется только один раз в неделю (используется понедельник как идентификатор недели)
   - Проверка через Redis: `week_summary:{pair_id}:{monday_date}`
3. **Содержание сообщения:**

**Silent Mode:**
```
"Вы уже {N} дней тихо проверяете друг друга. Это забота без слов."
```

**Chat Mode:**
```
"Уже {N} дней подряд вы засыпаете и просыпаетесь вместе ❤️"
```

Где `{N}` — количество дней с обменами картинками за последние 7 дней.

4. **Отправка:**
   - Сообщение отправляется обоим пользователям пары
   - После отправки флаг сохраняется в Redis на 8 дней (чтобы покрыть полную неделю)

**Технические детали:**
- Реализовано в функции `send_week_summary()` в `src/worker/jobs.py`
- Использует метод `get_week_stats()` из `DailyStateRepository` для подсчёта дней
- Статистика считается по полям `morning_responded_at` и `evening_responded_at` (день засчитывается, если был хотя бы один ответ)

## Возможные проблемы и их решения

### Проблема 1: Путаница с ролями "user A" и "user B"

**Проблема:** В коде используются термины "user A" и "user B", но они не соответствуют ролям "инициатор" и "получатель".

**Решение:** 
- `uid_a` и `uid_b` — только технические идентификаторы
- Инициатор и Получатель определяются динамически через `daily_state.morning_initiator` / `daily_state.evening_initiator`

### Проблема 2: Одновременное нажатие кнопок

**Проблема:** Оба пользователя могут нажать кнопку одновременно.

**Решение:**
- Атомарная операция `set_morning_initiator` с `SELECT FOR UPDATE`
- Только первый пользователь становится инициатором
- Второму показывается сообщение: "Ваш партнёр уже отправил пожелание"

### Проблема 3: Повторные ответы

**Проблема:** Получатель может попытаться ответить несколько раз.

**Решение:**
- Проверка `morning_responded_at IS NULL` перед отправкой ответа
- Если ответ уже был отправлен, показывается: "Вы уже ответили на пожелание"

### Проблема 4: Ответ инициатора на своё же сообщение

**Проблема:** Инициатор может попытаться ответить на своё же пожелание.

**Решение:**
- Проверка: `daily_state.morning_initiator != current_user.id`
- Если инициатор пытается ответить, показывается: "Вы уже отправили пожелание"

## Примеры сценариев

### Сценарий 1: Успешный обмен (Silent Mode)

**Важно:** Утренний и вечерний обмены независимы — инициаторы могут быть разными.

**Утро:**
1. **07:30 UTC** — Бот отправляет обоим пользователям: "Хотите отправить пожелание с «Добрым утром»?"
2. **07:35 UTC** — Пользователь А нажимает кнопку первым → становится **утренним Инициатором**
3. **07:35 UTC** — Пользователь В получает картинку "Со мной всё в порядке ❤️" с кнопкой
4. **08:00 UTC** — Пользователь В нажимает "Отправить в ответ" → отвечает на пожелание
5. **08:00 UTC** — Пользователь А получает картинку "Со мной всё в порядке ❤️"
6. ✅ Утренний обмен завершён

**Вечер (независимо от утра):**
7. **21:30 UTC** — Бот отправляет обоим пользователям: "Хотите отправить пожелание с «Спокойной ночи»?"
8. **21:35 UTC** — Пользователь В нажимает кнопку первым → становится **вечерним Инициатором** (может быть другой, чем утром!)
9. **21:35 UTC** — Пользователь А получает картинку "Я в безопасности, спокойной ночи ❤️" с кнопкой
10. **22:00 UTC** — Пользователь А нажимает "Отправить в ответ" → отвечает на пожелание
11. **22:00 UTC** — Пользователь В получает картинку "Я в безопасности, спокойной ночи ❤️"
12. ✅ Вечерний обмен завершён, оба пользователя подтвердили, что всё в порядке

**Итог дня:**
- Утром инициатором был Пользователь А
- Вечером инициатором был Пользователь В
- Оба обмена независимы и завершены успешно

### Сценарий 2: Нет ответа (с напоминаниями)

1. **07:30 UTC** — Бот отправляет обоим пользователям: "Хотите отправить пожелание с «Добрым утром»?"
2. **07:35 UTC** — Пользователь А нажимает кнопку → становится Инициатором
3. **07:35 UTC** — Пользователь В получает картинку "Со мной всё в порядке ❤️" (Silent Mode) или "Доброе утро, солнце ☀️" (Chat Mode) с кнопкой
4. **09:35 UTC (через 2 часа)** — Пользователь В получает: "Ваш близкий ждёт подтверждения что у вас всё хорошо."
5. **11:35 UTC (через 4 часа)** — Пользователь В получает: "Ваш близкий ждёт подтверждения что у вас всё хорошо."
6. **13:35 UTC (через 6 часов)** — Пользователь В получает: "Ваш близкий ждёт подтверждения что у вас всё хорошо."
7. **17:35 UTC (через 10 часов)** — Пользователь А получает: "⚠️ @username не отвечает, воспользуйтесь другим способом узнать, всё ли у него в порядке" [Кнопка: "❌ Отменить напоминания"]
8. **18:35 UTC (через 11 часов)** — Пользователь А получает то же предупреждение (если не нажал кнопку отмены)

### Сценарий 3: Одновременное нажатие

**Ситуация:** Оба пользователя видят запрос от бота и оба хотят отправить пожелание первыми.

1. **07:30 UTC** — Бот отправляет обоим пользователям: "Хотите отправить пожелание с «Добрым утром»?"
2. **07:35 UTC** — Пользователь А и Пользователь В нажимают кнопку "Отправить в ответ" почти одновременно
3. **Результат:** 
   - Только один из них (например, Пользователь А) становится **Инициатором** благодаря атомарной операции в БД
   - Пользователь А видит: "✅ Вы отправили пожелание"
   - Пользователь В видит: "Ваш партнёр уже отправил пожелание"
   - Пользователь В получает картинку от Пользователя А с кнопкой "Отправить в ответ"
   - Теперь Пользователь В становится **Получателем** и должен ответить на пожелание

**Важно:** Это нормальное поведение системы. Не важно, кто нажал первым — главное, что один становится инициатором, а второй получателем, и обмен картинками происходит в любом случае.

### Сценарий 4: Micro-Surprise в Chat Mode

1. **07:30 UTC** — Бот отправляет обоим пользователям: "Утро! Отправьте доброе пожелание в ответ:"
2. **07:35 UTC** — Пользователь А нажимает кнопку → становится Инициатором
3. **07:35 UTC** — Бот проверяет:
   - Генерирует случайное число от 1 до 4
   - Если выпало "1" И с момента последнего сюрприза прошло ≥ 72 часов → используется случайная подпись из массива
   - Например: "Доброе утро ☀️… а теперь иди целуй меня"
4. **07:35 UTC** — Пользователь В получает картинку с подписью-сюрпризом
5. ✅ Micro-Surprise применён, `last_surprise_at` обновлён

### Сценарий 5: Итог недели

1. **Понедельник, 00:00 UTC** — Бот проверяет все активные пары
2. Для каждой пары подсчитывается количество дней с обменами за последние 7 дней
3. Если дней > 0 и итог ещё не отправлялся на этой неделе:
   - **Silent Mode:** "Вы уже {N} дней тихо проверяете друг друга. Это забота без слов."
   - **Chat Mode:** "Уже {N} дней подряд вы засыпаете и просыпаетесь вместе ❤️"
4. Сообщение отправляется обоим пользователям пары
5. Флаг отправки сохраняется в Redis на 8 дней

### Сценарий 6: Окончание демо периода

1. **День 0:** Пара создана → `status = 'trial'`, `period_end = today + 7 дней`
2. **День 1-7:** Демо период активен, бот работает в полном режиме
3. **День 8, 10:00 UTC:** Задача `dunning_notifications` находит просроченную подписку
4. **День 8, 10:00 UTC:** Статус пары меняется на `past_due`
5. **День 8, 10:00 UTC:** Обоим пользователям отправляется уведомление с кнопкой оплаты
6. **День 8, 07:30 UTC:** Утром вместо обычного запроса отправляется:
   ```
   "Демо режим закончился. Для продолжения работы бота выберите тариф и оплатите подписку."
   [Кнопка: "Выбрать тариф"]
   ```
7. **День 8, 21:30 UTC:** Вечером аналогичное уведомление
8. **При попытке использовать старые кнопки:** Показывается сообщение о просрочке
9. **После оплаты:** Статус меняется на `active`, работа бота возобновляется

### Сценарий 7: Удаление старых сообщений

1. **Каждый час в :30 минут:** Запускается задача `cleanup_old_messages`
2. Находятся все сообщения в таблице `bot_messages`, где `sent_at < NOW() - 48 hours`
3. Для каждого сообщения:
   - Вызывается `delete_message_with_retry(chat_id, message_id)`
   - Если удаление успешно → запись удаляется из БД
   - Если сообщение уже удалено → запись удаляется из БД (считается успешным)
4. Чат бота остаётся чистым, старые сообщения автоматически удаляются

## Роли в системе подписки

### Пользователь (User)

**Роль:** Основной участник системы, член пары.

**Возможности:**
- **Создание пары:** Выбирает режим общения (Silent/Chat), приглашает партнёра через ссылку
- **Демо период:** Использует бота бесплатно в течение 7 дней после создания пары
- **Ежедневное взаимодействие:** 
  - Получает утренние и вечерние запросы от бота
  - Может стать инициатором, нажав кнопку первым
  - Может стать получателем и ответить на пожелание партнёра
- **Оплата:** Может оплатить подписку для продолжения использования после окончания демо
- **Просмотр статуса:** Команда `/subscription` показывает текущий статус подписки

**Ограничения:**
- После окончания демо периода (7 дней) требуется оплата для продолжения работы
- При статусе `past_due` все функции блокируются до оплаты
- Оба пользователя пары помечаются в `user_demo` — повторное использование демо невозможно

### Плательщик (Payer)

**Роль:** Пользователь, который оплачивает подписку для пары.

**Особенности:**
- Любой из двух пользователей пары может стать плательщиком
- После оплаты **оба пользователя** получают доступ к функциям бота
- При повторной оплате период продлевается от текущей даты окончания (если подписка ещё активна)
- Если подписка просрочена, новая оплата начинает период с текущей даты
- Информация о плательщике сохраняется в `pair.payer_id` и `user.payer_id`

**Процесс оплаты:**
1. Пользователь отправляет `/pay` или нажимает кнопку "Выбрать тариф"
2. Выбирает тариф из списка (1 месяц, 3 месяца, 6 месяцев, 1 год, Навсегда)
3. Переходит на страницу оплаты YooKassa
4. После успешной оплаты webhook обновляет подписку
5. Обоим пользователям отправляется уведомление об активации

### Система (Bot/Worker)

**Роль:** Автоматические задачи, выполняемые ботом и воркером.

#### Задачи воркера (Worker Tasks)

**morning_sender** (каждую минуту, проверка окна 07:30-08:30 UTC):
- Получает все активные пары (`status IN ('trial', 'active')`)
- Отправляет утренние запросы обоим пользователям пары
- Для пар со статусом `past_due` отправляет уведомление об окончании демо с кнопкой оплаты
- Сохраняет `message_id` всех отправленных сообщений для последующего удаления

**evening_sender** (каждую минуту, проверка окна 21:30-22:30 UTC):
- Аналогично `morning_sender`, но для вечерних запросов
- Для пар со статусом `past_due` отправляет уведомление об окончании демо

**dunning_notifications** (ежедневно в 10:00 UTC):
- Находит все просроченные подписки (`period_end < today`, `status IN ('trial', 'active')`)
- Переводит статус пары в `past_due`
- Отправляет обоим пользователям уведомление с кнопкой оплаты

**check_unanswered_pictures** (ежечасно в :00 минут):
- Проверяет неотвеченные пожелания
- Отправляет напоминания получателю через 2, 4, 6 часов
- Отправляет предупреждения инициатору через 10+ часов (каждый час до 24 часов)
- Использует Redis для предотвращения дубликатов

**send_week_summary** (ежедневно в 00:00 UTC):
- Подсчитывает количество дней с обменами за последние 7 дней
- Отправляет итог недели активным парам (один раз в неделю)
- Использует Redis для предотвращения повторной отправки

**cleanup_old_messages** (ежечасно в :30 минут):
- Находит все сообщения старше 48 часов в таблице `bot_messages`
- Удаляет их через Telegram API
- Удаляет записи из БД для успешно удалённых сообщений

**cleanup_old_data** (ежедневно в 03:00 UTC):
- Удаляет старые записи `daily_state` старше 31 дня

#### Обработчики бота (Bot Handlers)

**handle_start_logic** (`/start`):
- Создаёт пользователя, если его нет
- Обрабатывает создание пары через ссылку-приглашение
- Проверяет использование демо периода
- Создаёт подписку с демо периодом 7 дней

**handle_request_morning / handle_request_evening**:

### Администратор (Admin)

**Роль:** Пользователь с расширенными правами для управления ботом и отладки.

**Определение:**
- Администратор определяется через переменную окружения `ADMIN_TG_ID` в `.env`
- Проверка прав выполняется функцией `is_admin(tg_id)` в `src/bot/handlers/admin.py`
- Только пользователь с `tg_id == ADMIN_TG_ID` имеет доступ к административным командам

**Доступные команды:**

#### `/admin`
Показывает статистику бота:
- Всего пользователей
- Всего пар
- Одиночных пользователей (без пары)
- Пользователей с демо (в таблице `user_demo`)
- Пользователей на подписке (с активными подписками)

**Пример использования:**
```
/admin
```

**Ответ:**
```
📊 Статистика бота

👥 Всего пользователей: 150
💑 Всего пар: 75
👤 Одиночных пользователей: 0
🎁 Пользователи с демо: 120
💳 Пользователи на подписке: 30
```

#### `/reset_demo <tg_id_пользователя>`
Сбрасывает демо режим для указанного пользователя.

**Важно:**
- Если пользователь состоит в паре, демо сбрасывается **автоматически для обоих** пользователей пары
- Сброс демо **НЕ меняет** статус пары (`pair.status`) и статус подписки (`subscription.status`)
- Сброс демо только удаляет записи из таблицы `user_demo`, что позволяет пользователям снова использовать демо период при создании **новой** пары
- Если пара уже существует, сброс демо не вернёт её в статус `trial` — для этого нужно удалить пару (`/delete`) и создать новую

**Процесс сброса:**
1. Администратор отправляет `/reset_demo <tg_id>`
2. Система находит пользователя по `tg_id`
3. Если пользователь состоит в паре, система автоматически находит партнёра
4. Удаляются записи из таблицы `user_demo` для обоих пользователей (или одного, если не в паре)
5. Пользователи могут снова использовать демо период при создании новой пары

**Пример использования:**
```
/reset_demo 123456789
```

**Ответ (если пользователь в паре):**
```
✅ Демо режим сброшен для пары:
  • 123456789
  • 987654321

Сброшено для 2 из 2 пользователей.
```

**Ответ (если пользователь не в паре):**
```
✅ Демо режим сброшен для пользователя 123456789 (не состоит в паре)
```

**Когда использовать:**
- При тестировании бота
- Когда нужно повторно протестировать onboarding для пары
- Для сброса ограничений демо режима (например, если пользователи хотят создать новую пару с демо)

**Ограничения:**
- Команда не влияет на существующие пары и их статусы
- Для полного сброса демо режима существующей пары нужно:
  1. Удалить пару через `/delete` (выполняют оба пользователя)
  2. Сбросить демо через `/reset_demo` (выполняет администратор)
  3. Создать новую пару через `/start` с новой ссылкой-приглашением

**Техническая реализация:**
- Файл: `src/bot/handlers/admin.py`
- Функция проверки: `is_admin(tg_id: int) -> bool`
- Репозиторий: `UserDemoRepository.remove(tg_id)` — удаляет запись из `user_demo`
- Логирование: все действия администратора логируются с указанием `admin_tg_id` и `target_tg_ids`

## Заключение

Бот работает по принципу взаимного подтверждения:
- Каждый день оба пользователя должны обменяться картинками (утром и вечером)
- Первый пользователь отправляет пожелание → второй отвечает
- Если ответа нет — система напоминаний помогает пользователям не забыть друг о друге
- В Chat Mode периодически появляются Micro-Surprise подписи для разнообразия
- Раз в неделю пользователи получают итог недели с статистикой обменов
- После окончания демо периода (7 дней) требуется оплата подписки для продолжения работы
- Старые сообщения автоматически удаляются через 48 часов для поддержания чистоты чата
- Цель: убедиться, что с партнёром всё в порядке, сохраняя приватность и минимализм
