## Пошаговая инструкция по применению миграции

### Шаг 1: Проверка текущей ревизии базы данных

Перед применением миграции нужно проверить текущую ревизию на сервере:

```bash
python scripts/run_migration.py
```

Скрипт автоматически:
- Создаст SSH туннель к серверу (если нужно)
- Покажет текущую ревизию базы данных
- Применит все неприменённые миграции до `head`

**Ожидаемый результат:**
- Если миграция `replace_user_demo_pair` уже применена, то будет применена миграция `a703b4149630_add_nicknames_to_pairs`
- Если миграция `replace_user_demo_pair` не применена, сначала будет применена она, затем `a703b4149630_add_nicknames_to_pairs`

## Альтернативный способ: Ручное применение миграции

Если автоматический скрипт не работает, можно применить миграцию вручную:

### Вариант 1: Через Alembic напрямую

```bash
# Убедитесь, что SSH туннель создан (если нужно)
# Затем выполните:
alembic upgrade head
```

### Вариант 2: Через SQL напрямую на сервере

Если у вас есть прямой доступ к серверу:

```bash
# Подключитесь к серверу
ssh root@91.222.237.94

# Подключитесь к PostgreSQL
sudo -u postgres psql -d silent_couple_bot

# Выполните SQL команды из миграции:
DO $$ 
BEGIN
    -- Add nickname_a column if it doesn't exist
    IF NOT EXISTS (
        SELECT 1 FROM information_schema.columns 
        WHERE table_schema = 'public' 
        AND table_name = 'pairs'
        AND column_name = 'nickname_a'
    ) THEN
        ALTER TABLE pairs 
        ADD COLUMN nickname_a TEXT;
    END IF;
    
    -- Add nickname_b column if it doesn't exist
    IF NOT EXISTS (
        SELECT 1 FROM information_schema.columns 
        WHERE table_schema = 'public' 
        AND table_name = 'pairs'
        AND column_name = 'nickname_b'
    ) THEN
        ALTER TABLE pairs 
        ADD COLUMN nickname_b TEXT;
    END IF;
END $$;

# Проверьте результат:
\d pairs

# Выйдите из psql:
\q
```

## Возможные проблемы и решения

### Проблема 1: Миграция не применяется

**Симптомы:** Скрипт показывает ошибку или миграция не видна

**Решение:**
1. Проверьте, что SSH туннель создан корректно
2. Проверьте, что `.env` файл настроен правильно
3. Проверьте текущую ревизию: `alembic current`
4. Проверьте историю миграций: `alembic history`

### Проблема 2: Колонки уже существуют

**Симптомы:** Ошибка "column already exists"

**Решение:**
Миграция использует условную логику (`IF NOT EXISTS`), поэтому эта ошибка не должна возникать. Если возникает, проверьте структуру таблицы вручную.

### Проблема 3: Бот не видит новые колонки

**Симптомы:** После применения миграции бот не может использовать никнеймы

**Решение:**
1. Перезапустите бота после применения миграции
2. Убедитесь, что код обновлён на всех ПК, где запускается бот
3. Проверьте логи бота на наличие ошибок SQL
