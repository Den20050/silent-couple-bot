## Общее описание

**Silent Couple Bot** — это Telegram-бот для пар, который помогает поддерживать связь через ежедневный обмен картинками "Доброе утро" и "Спокойной ночи".

### Основная идея

Бот решает проблему поддержания связи между партнёрами, которые:
- Живут на расстоянии друг от друга
- Редко общаются в течение дня
- Хотят быть уверены, что с близким человеком всё в порядке

### Как это работает

1. **Ежедневно** бот предлагает обоим пользователям пары отправить пожелание
2. **Первый**, кто нажмёт кнопку, отправляет картинку партнёру
3. **Второй** должен ответить своей картинкой
4. Если кто-то не отвечает — бот отправляет напоминания

### Ключевые особенности

- ✅ **Два режима работы**: для пар, которые часто общаются, и для тех, кто редко
- ✅ **Демо-период**: 7 дней бесплатного использования
- ✅ **Мультивалютная оплата**: поддержка 10 валют (RUB, EUR, USD, UAH, BYN, KZT, AED, THB, TRY, CNY)
- ✅ **Автоматические напоминания**: если партнёр не отвечает
- ✅ **Умные уведомления**: учитывают часовой пояс каждого пользователя
- ✅ **Micro-Surprise**: случайные тёплые подписи для разнообразия (только в Chat Mode)

## Роли пользователей

### 1. Обычные пользователи (User)

**Описание:** Основные пользователи бота — участники пар.

**Возможности:**
- Создание пары с партнёром
- Выбор режима общения (Chat Mode или Silent Mode)
- Ежедневный обмен картинками
- Просмотр статуса подписки
- Оплата подписки
- Удаление аккаунта (GDPR)

**Ограничения:**
- Один пользователь может быть только в одной активной паре
- Демо-период можно использовать только один раз
- После окончания демо-периода требуется оплата подписки

### 2. Администратор (Admin)

**Описание:** Пользователь с расширенными правами для управления ботом.

**Определение:** Администратор определяется через переменную окружения `ADMIN_TG_ID` в файле `.env`.

**Возможности:**

#### 📊 Статистика (`/admin` или `/admin_stats`)
- Общее количество пользователей
- Количество активных пар
- Количество пользователей без пары
- Количество пар в демо-режиме
- Количество активных подписок
- Количество просроченных подписок

#### 🔄 Сброс демо-режима (`/admin_reset_demo`)
- Сброс демо-периода для конкретного пользователя или пары
- Позволяет пользователям снова использовать демо-период
- Формат команды:
  - Для одного пользователя: `/admin_reset_demo <tg_id>`
  - Для пары: `/admin_reset_demo <tg_id_1> <tg_id_2>`

#### 🎁 Подарок подписки (`/admin_gift`)
- Подарок подписки пользователю или паре
- Выбор тарифа (1 месяц, 3 месяца, 6 месяцев, 1 год, Навсегда)
- Автоматическая активация подписки для обоих пользователей пары
- Формат команды:
  - `/admin_gift <tg_id>` — затем выбор тарифа

#### 📢 Рассылка сообщений (`/admin_broadcast`)
- Массовая рассылка сообщений всем пользователям бота
- Отправка HTML-форматированных сообщений
- Статистика отправки (успешно/неудачно)

**Безопасность:**
- Все команды проверяют права администратора
- Неавторизованные пользователи получают сообщение "Доступ запрещён"
- Все действия администратора логируются

## Режимы работы

Бот поддерживает два режима общения, которые выбираются при создании пары и не могут быть изменены позже.

### 1. Chat Mode (💬 Часто общаемся)

**Для кого:** Для пар, которые часто общаются в личных чатах.

**Особенности:**
- Более дружелюбные и неформальные тексты сообщений
- **Micro-Surprise**: случайные тёплые подписи к картинкам (примерно раз в 3-4 дня)
- Картинки отправляются в личный чат с ботом
- Подписи к картинкам:
  - Утро: "Доброе утро, солнце ☀️" (или случайная подпись из Micro-Surprise)
  - Вечер: "Спокойной ночи, мой человек 🌙" (или случайная подпись)

**Примеры сообщений:**
- Запрос утром: "Утро! Отправьте доброе пожелание в ответ:"
- Запрос вечером: "Вечер! Отправьте пожелание на ночь:"
- Напоминание: "Ваш близкий ждёт ответа. Отправьте пожелание в ответ:"

### 2. Silent Mode (💔 Редко)

**Для кого:** Для пар, которые редко общаются и нужен сигнал о том, что всё в порядке.

**Особенности:**
- Более формальные и нейтральные тексты сообщений
- Фокус на безопасности и подтверждении благополучия
- Картинки отправляются в личный чат с ботом
- Подписи к картинкам:
  - Утро: "Со мной всё в порядке ❤️"
  - Вечер: "Я в безопасности, спокойной ночи ❤️"

**Примеры сообщений:**
- Запрос утром: "Хотите отправить пожелание с \"Добрым утром\"?"
- Запрос вечером: "Хотите отправить пожелание с \"Спокойной ночи\"?"
- Напоминание: "Ваш близкий ждёт подтверждения что у вас всё хорошо."

## Алгоритм работы бота

### 1. Создание пары (Onboarding)

#### Шаг 1: Пользователь А (Приглашающий)

1. Отправляет команду `/start`
2. Бот показывает политику конфиденциальности
3. Пользователь нажимает кнопку "Принимаю ✅"
4. Бот предлагает выбрать режим общения:
   - 💬 Часто общаемся → Chat Mode
   - 💔 Редко → Silent Mode
5. После выбора режима бот создаёт ссылку-приглашение: `/start <tg_id_пользователя_А>`
6. Пользователь А отправляет ссылку партнёру

#### Шаг 2: Пользователь В (Приглашённый)

1. Переходит по ссылке-приглашению (`/start <tg_id_пользователя_А>`)
2. Бот показывает политику конфиденциальности
3. Пользователь нажимает кнопку "Принимаю ✅"
4. Пара создаётся автоматически с режимом, выбранным Пользователем А
5. Оба пользователя получают уведомление о создании пары

#### Результат создания пары

**В базе данных создаются записи:**

**Таблица `pairs`:**
- `uid_a` = ID пользователя А (приглашающего)
- `uid_b` = ID пользователя В (приглашённого)
- `mode` = режим, выбранный пользователем А (`chat` или `silent`)
- `status` = `trial` (демо режим)

**Таблица `subscriptions`:**
- `pair_id` = ID созданной пары
- `payer_id` = ID пользователя А (по умолчанию)
- `status` = `trial`
- `period_end` = сегодня + 7 дней (настраивается через `TRIAL_PERIOD_DAYS`)

**Таблица `user_demo`:**
- Оба пользователя помечаются как использовавшие демо-период
- Это предотвращает повторное использование демо-периода

### 2. Ежедневный обмен картинками

#### 2.1. Утренние картинки (07:30-08:30 UTC)

**Временное окно:** Настраивается через переменные окружения:
- `MORNING_START_TIME` (по умолчанию 07:30 UTC)
- `MORNING_END_TIME` (по умолчанию 08:30 UTC)

**Важно:** Бот учитывает часовой пояс каждого пользователя. Если пользователь находится в часовом поясе UTC+3, то утреннее окно для него будет 10:30-11:30 по местному времени.

**Алгоритм:**

**Шаг 1: Бот отправляет запросы обоим пользователям**

Воркер `morning_sender` запускается каждую минуту и проверяет:
- Есть ли активные пары (`status IN ('trial', 'active')`)
- Находится ли хотя бы один из пользователей пары в своём утреннем временном окне

Если условия выполнены, бот отправляет обоим пользователям сообщение с кнопкой:

**Chat Mode:**
```
Утро! Отправьте доброе пожелание в ответ:
[Кнопка: "Отправить в ответ"]
```

**Silent Mode:**
```
Хотите отправить пожелание с "Добрым утром"?
[Кнопка: "Отправить в ответ"]
```

**Шаг 2: Первый пользователь нажимает кнопку (становится Инициатором)**

- Пользователь нажимает кнопку "Отправить в ответ"
- Бот атомарно устанавливает `daily_state.morning_initiator = user_id`
- Если другой пользователь уже нажал — показывается сообщение: "Ваш партнёр уже отправил пожелание"
- Инициатору показывается: "✅ Вы отправили пожелание"
- Бот выбирает случайную картинку из коллекции утренних картинок

**Шаг 3: Бот отправляет картинку Получателю**

Получатель (второй пользователь пары) получает картинку с подписью:

**Chat Mode:**
- Стандартная подпись: "Доброе утро, солнце ☀️"
- Или случайная подпись из Micro-Surprise (если прошло ≥72 часов с последнего сюрприза)

**Silent Mode:**
- Подпись: "Со мной всё в порядке ❤️"

К картинке прикреплена кнопка: "Отправить в ответ"

**Шаг 4: Получатель отвечает**

- Получатель нажимает кнопку "Отправить в ответ"
- Бот проверяет:
  - ✅ Пользователь действительно является получателем (не инициатором)
  - ✅ Ответ ещё не был отправлен (`morning_responded_at IS NULL`)
- Бот отправляет новую случайную картинку Инициатору
- Устанавливается `daily_state.morning_responded_at = NOW()`
- Сообщение Получателя редактируется: "✅ Вы ответили на пожелание"

**Результат:**
- Инициатор получил картинку от Получателя
- Обмен завершён
- Оба пользователя подтвердили, что всё в порядке

#### 2.2. Вечерние картинки (21:30-22:30 UTC)

**Временное окно:** Настраивается через переменные окружения:
- `EVENING_START_TIME` (по умолчанию 21:30 UTC)
- `EVENING_END_TIME` (по умолчанию 22:30 UTC)

**Алгоритм полностью аналогичен утренним картинкам:**

**Шаг 1:** Бот отправляет запросы обоим пользователям

**Chat Mode:**
```
Вечер! Отправьте пожелание на ночь:
[Кнопка: "Отправить в ответ"]
```

**Silent Mode:**
```
Хотите отправить пожелание с "Спокойной ночи"?
[Кнопка: "Отправить в ответ"]
```

**Шаг 2:** Первый пользователь нажимает кнопку (становится Инициатором)

**Шаг 3:** Бот отправляет картинку Получателю

**Chat Mode:**
- Стандартная подпись: "Спокойной ночи, мой человек 🌙"
- Или случайная подпись из Micro-Surprise

**Silent Mode:**
- Подпись: "Я в безопасности, спокойной ночи ❤️"

**Шаг 4:** Получатель отвечает

### 3. Система напоминаний

#### 3.1. Напоминания Получателю (3, 6, 9 часов после отправки)

**Задача:** Напомнить получателю, что нужно ответить на пожелание.

**Алгоритм:**
- Воркер `check_unanswered_pictures` запускается каждый час
- Проверяет все пары, где:
  - Картинка была отправлена (есть `morning_initiator` или `evening_initiator`)
  - Ответ ещё не был получен (`morning_responded_at IS NULL` или `evening_responded_at IS NULL`)
  - Прошло 3, 6 или 9 часов с момента отправки картинки
  - Пара имеет статус `trial` или `active` (не `past_due`)

**Сообщения:**

**Chat Mode:**
```
Ваш близкий ждёт ответа. Отправьте пожелание в ответ:
[Кнопка: "Отправить в ответ"]
```

**Silent Mode:**
```
Ваш близкий ждёт подтверждения что у вас всё хорошо.
[Кнопка: "Отправить в ответ"]
```

**Важно:** Напоминания отправляются только для активных пар. Для пар со статусом `past_due` напоминания не отправляются.

#### 3.2. Предупреждения Инициатору (начиная с 10 часов, затем каждый час)

**Задача:** Уведомить инициатора, что получатель не отвечает.

**Алгоритм:**
- Воркер `check_unanswered_pictures` проверяет все пары, где:
  - Картинка была отправлена более 10 часов назад
  - Ответ ещё не был получен
  - Пара имеет статус `trial` или `active`

**Первое предупреждение (10 часов):**

**Chat Mode:**
```
@{username} ещё не ответил(а) на ваше пожелание. Всё в порядке?
[Кнопка: "Отменить предупреждения"]
```

**Silent Mode:**
```
@{username} ещё не подтвердил(а), что всё в порядке. Всё в порядке?
[Кнопка: "Отменить предупреждения"]
```

**Последующие предупреждения (11, 12, 13, ..., 24 часа):**
- Отправляются каждый час до 24 часов с момента отправки картинки
- Инициатор может отменить предупреждения, нажав кнопку "Отменить предупреждения"

**Важно:** Предупреждения отправляются только для активных пар. Для пар со статусом `past_due` предупреждения не отправляются.

### 4. Micro-Surprise (только для Chat Mode)

**Назначение:** Разнообразить общение в Chat Mode, добавляя случайные тёплые подписи к картинкам.

**Как работает:**

1. **Частота:** Примерно раз в 3-4 дня (случайно, без привязки ко времени суток)
2. **Механизм:**
   - При формировании сообщения генерируется случайное число от 1 до 4
   - Если выпадает "1" **И** с момента последнего сюрприза прошло ≥ 72 часов → используется случайная подпись из массива сюрпризов
   - Иначе используется стандартная подпись
3. **Хранение:** В `daily_state.last_surprise_at` сохраняется время последнего сюрприза

**Подписи для утренних картинок:**
- "Доброе утро ☀️… а теперь иди целуй меня"
- "Твоё утро начинается со мня — и это прекрасно"
- "Доброе утро, солнце ☀️"

**Подписи для вечерних картинок:**
- "Засыпай — я рядом, даже если молчу"
- "Спокойной ночи… и не думай о ком-то другом ❤️"
- "Спокойной ночи, мой человек 🌙"

**Технические детали:**
- Реализовано в функции `get_caption_with_surprise()` в `src/bot/handlers/callbacks.py`
- Используется в обработчиках отправки картинок
- После использования сюрприза обновляется `daily_state.last_surprise_at`
- Минимальный интервал между сюрпризами: 72 часа (3 дня)

### 5. Окончание демо-периода

#### 5.1. Обнаружение просрочки

**Воркер:** `dunning_notifications` (запускается ежедневно в 10:00 UTC)

**Алгоритм:**
1. Находит все подписки, где:
   - `period_end < today`
   - `status IN ('trial', 'active')`
   - `is_lifetime = False` (исключаются бессрочные подписки)
2. Для каждой найденной подписки:
   - Обновляет статус пары на `past_due`
   - Обновляет статус подписки на `past_due`
   - Отправляет обоим пользователям уведомление с кнопкой оплаты

**Уведомление:**
```
Демо режим закончился. Для продолжения работы бота выберите тариф и оплатите подписку.
[Кнопка: "Выбрать тариф"]
```

#### 5.2. Уведомления после окончания демо-периода

**Воркер:** `morning_sender` (только утром, не вечером)

**Расписание:**
- **Первые 3 дня после окончания:** уведомление отправляется каждое утро
- **После 3 дней:** уведомление отправляется раз в 7 дней (только утром)

**Алгоритм:**
1. Воркер получает все пары со статусом `past_due`
2. Для каждой пары проверяет:
   - Сколько дней прошло с момента окончания демо-периода
   - Было ли уже отправлено уведомление сегодня (через Redis или базу данных)
3. Если условия выполнены — отправляет уведомление обоим пользователям

**Важно:**
- Для пар со статусом `past_due`:
  - ❌ Не отправляются обычные утренние/вечерние запросы
  - ❌ Не отправляются напоминания об ответах
  - ✅ Отправляются только уведомления об окончании демо-периода

### 6. Оплата подписки

#### 6.1. Процесс оплаты

**Шаг 1: Выбор валюты**
- Пользователь отправляет `/pay` или нажимает кнопку "Выбрать тариф"
- Бот показывает список доступных валют:
  - RUB (Российский рубль) ₽
  - EUR (Евро) €
  - USD (Доллар США) $
  - UAH (Украинская гривна) ₴
  - BYN (Белорусский рубль) Br
  - KZT (Казахстанский тенге) ₸
  - AED (Дирхам ОАЭ) د.إ
  - THB (Тайский бат) ฿
  - TRY (Турецкая лира) ₺
  - CNY (Китайский юань) ¥

**Шаг 2: Выбор тарифа**
- После выбора валюты бот показывает список тарифов с ценами в выбранной валюте:
  - 1 месяц
  - 3 месяца (экономия указана)
  - 6 месяцев (экономия указана)
  - 1 год (экономия указана)
  - Навсегда (бессрочная подписка)

**Шаг 3: Переход на оплату**
- Пользователь выбирает тариф
- Бот создаёт ссылку на оплату через Robokassa
- Пользователь переходит на страницу оплаты Robokassa
- Оплата может быть выполнена картой, электронными кошельками и другими способами, поддерживаемыми Robokassa

**Шаг 4: Обработка оплаты**
- После успешной оплаты Robokassa отправляет webhook на сервер
- Бот проверяет подпись платежа
- Обновляет подписку:
  - `status` = `active`
  - `period_end` = продлевается на выбранный период
  - `is_lifetime` = `true` (если выбран тариф "Навсегда")
- Обновляет статус пары: `status` = `active`
- **Сбрасывает `daily_state`** для сегодняшнего дня (очищает все состояния)
- Сбрасывает `last_past_due_notification_date` в подписке
- Отправляет обоим пользователям уведомление об активации подписки

**Уведомление об активации:**
```
✅ Подписка активна до {дата}
```

**Важно:**
- Оплачивает один из пользователей пары
- После оплаты подписка активируется для обоих пользователей
- Подписка автоматически продлевается при следующей оплате (если текущий период ещё не истёк)
- При оплате все предыдущие состояния (`daily_state`) сбрасываются — пара начинает работу "с чистого листа"

## Система подписок и тарифы

### Статусы подписки

1. **`trial`** — пробный период (7 дней, настраивается через `TRIAL_PERIOD_DAYS`)
2. **`active`** — активная подписка (оплачена)
3. **`past_due`** — подписка просрочена (нужно оплатить)
4. **`cancelled`** — подписка отменена
5. **`refunded`** — подписка возвращена (для будущего использования)

### Тарифы

Все тарифы настраиваются через переменную окружения `SUBSCRIPTION_PRICES` в формате JSON.

**Доступные тарифы:**

1. **1 месяц** — 30 дней
2. **3 месяца** — 90 дней (экономия относительно месячного тарифа)
3. **6 месяцев** — 180 дней (экономия относительно месячного тарифа)
4. **1 год** — 365 дней (экономия относительно месячного тарифа)
5. **Навсегда** — бессрочная подписка (до 2099-12-31)

**Пример цен в рублях (RUB):**
- 1 месяц: 199 ₽
- 3 месяца: 549 ₽ (экономия 48 ₽)
- 6 месяцев: 969 ₽ (экономия 225 ₽)
- 1 год: 1699 ₽ (экономия 689 ₽)
- Навсегда: 3899 ₽

**Важно:** Цены в иностранных валютах включают надбавку +25% от цены в рублях (из-за конвертации и тарифа Robokassa).

### Поддерживаемые валюты

Бот поддерживает оплату в 10 валютах:
- RUB (Российский рубль) ₽
- EUR (Евро) €

- UAH (Украинская гривна) ₴
- BYN (Белорусский рубль) Br
- KZT (Казахстанский тенге) ₸

### Платежная система

**Robokassa** — используется для обработки платежей.

**Особенности:**
- Поддержка множества способов оплаты (карты, электронные кошельки и т.д.)

## Административные функции

### 1. Статистика (`/admin` или `/admin_stats`)

**Описание:** Показывает общую статистику по боту.

**Данные:**
- Общее количество пользователей
- Количество активных пар
- Количество пользователей без пары
- Количество пар в демо-режиме (`trial`)
- Количество активных подписок (`active`)
- Количество просроченных подписок (`past_due`)

**Пример вывода:**
```
📊 Статистика бота:

👥 Всего пользователей: 150
💑 Активных пар: 75
👤 Пользователей без пары: 0
🆓 Пар в демо-режиме: 10
✅ Активных подписок: 65
⏳ Просроченных подписок: 0
```

### 2. Сброс демо-режима (`/admin_reset_demo`)

**Описание:** Позволяет сбросить демо-период для пользователя или пары.

**Использование:**
- Для одного пользователя: `/admin_reset_demo <tg_id>`
- Для пары: `/admin_reset_demo <tg_id_1> <tg_id_2>`

**Что происходит:**
1. Удаляется запись из таблицы `user_demo` для указанных пользователей
2. Пользователи могут снова использовать демо-период при создании новой пары

**Важно:** Это не продлевает текущий демо-период, а только позволяет использовать демо-период снова в будущем.

### 3. Подарок подписки (`/admin_gift`)

**Описание:** Позволяет подарить подписку пользователю или паре.

**Использование:**
1. `/admin_gift <tg_id>` — указывается Telegram ID пользователя
2. Бот проверяет, что пользователь состоит в паре
3. Бот показывает список тарифов для выбора
4. После выбора тарифа:
   - Обновляется подписка пары
   - Статус пары меняется на `active`
   - Сбрасывается `daily_state` для сегодняшнего дня
   - Обоим пользователям отправляется уведомление о подаренной подписке

**Доступные тарифы:**
- 1 месяц
- 3 месяца
- 6 месяцев
- 1 год
- Навсегда

**Уведомление пользователям:**
```
🎁 Вам подарена подписка до {дата}!
```

### 4. Рассылка сообщений (`/admin_broadcast`)

**Описание:** Позволяет отправить сообщение всем пользователям бота.

**Использование:**
1. `/admin_broadcast` — запускает процесс рассылки
2. Бот просит ввести сообщение
3. Пользователь отправляет сообщение (поддерживается HTML-форматирование)
4. Бот отправляет сообщение всем пользователям из таблицы `users`
5. Показывает статистику:
   - Количество успешно отправленных сообщений
   - Количество неудачных отправок

**Пример использования:**
```
Админ: /admin_broadcast
Бот: Введите сообщение для рассылки...
Админ: <b>Важное обновление!</b> Бот будет недоступен с 00:00 до 06:00 UTC.
Бот: ✅ Рассылка отправлена 150 пользователям. Неудачных отправок: 0.
```

**Важно:** Рассылка отправляется всем пользователям, включая тех, кто не состоит в паре.

## Технические детали

### Архитектура

**Компоненты:**
1. **Bot** — основной бот (aiogram)
2. **Worker** — воркер для выполнения фоновых задач (Arq)
3. **Webhook Server** — сервер для обработки webhook от Robokassa (FastAPI)

### База данных

**Основные таблицы:**
- `users` — пользователи бота
- `pairs` — пары пользователей
- `subscriptions` — подписки пар
- `daily_state` — ежедневное состояние пар (инициаторы, ответы и т.д.)
- `user_demo` — пользователи, использовавшие демо-период
- `bot_messages` — сообщения бота (для удаления старых сообщений)
- `lifetime_pair_history` — история бессрочных подписок

### Воркеры (Cron Jobs)

**morning_sender** (каждую минуту):
- Проверяет утреннее временное окно для каждой пары
- Отправляет запросы на отправку картинок
- Обрабатывает уведомления для пар со статусом `past_due`

**evening_sender** (каждую минуту):
- Проверяет вечернее временное окно для каждой пары
- Отправляет запросы на отправку картинок

**dunning_notifications** (ежедневно в 10:00 UTC):
- Находит просроченные подписки
- Переводит статус пары в `past_due`
- Отправляет уведомления об окончании демо-периода

**check_unanswered_pictures** (ежечасно в :00 минут):
- Проверяет неотвеченные картинки
- Отправляет напоминания получателю (3, 6, 9 часов)
- Отправляет предупреждения инициатору (10+ часов, каждый час)

**send_week_summary** (ежедневно в 00:00 UTC):
- Отправляет еженедельную статистику парам

**send_share_nudge** (ежедневно в 14:00 UTC):
- Отправляет напоминания о возможности поделиться ботом

**cleanup_old_messages** (ежечасно в :30 минут):
- Удаляет старые сообщения бота из чатов пользователей

### Redis

**Использование:**
- Хранение состояний FSM (Finite State Machine)
- Блокировки для предотвращения параллельного выполнения задач
- Отслеживание отправленных уведомлений
- Rate limiting

**Fallback:** Если Redis недоступен, бот использует:
- MemoryStorage для FSM (состояния теряются при перезапуске)
- База данных для отслеживания уведомлений

### Безопасность

1. **Проверка подписи платежей:** Все webhook от Robokassa проверяются на подлинность
2. **Rate limiting:** Ограничение количества запросов от одного пользователя
3. **Админские команды:** Проверка прав администратора перед выполнением команд
4. **Атомарные операции:** Использование транзакций БД для критических операций

### Логирование

**Используется:** `structlog` для структурированного логирования

**Уровни логирования:**
- `DEBUG` — детальная информация для отладки
- `INFO` — общая информация о работе бота
- `WARNING` — предупреждения (например, Redis недоступен)
- `ERROR` — ошибки с полным стеком вызовов
