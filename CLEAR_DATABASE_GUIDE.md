# Руководство по очистке базы данных

## ⚠️ ВНИМАНИЕ

**Эта операция необратима!** Все пользовательские данные будут удалены без возможности восстановления.

## Что будет очищено

Миграция `df533770ed60_clear_all_user_data` очистит следующие таблицы:

1. **daily_state** — ежедневные состояния пар
2. **subscriptions** — подписки
3. **lifetime_pair_history** — история пар с lifetime подписками
4. **pair_demo** — блок-лист использованных демо
5. **pairs** — пары пользователей
6. **bot_messages** — сообщения бота (служебная таблица)
7. **users** — пользователи

## Что НЕ будет очищено

- **pics_pool** — пул картинок (общие ресурсы, не пользовательские данные)
- Структура таблиц — все таблицы останутся, но будут пустыми
- Последовательности (sequences) — будут сброшены на начало (начнут с 1)

## Как применить миграцию

### Способ 1: Автоматический (рекомендуется)

Используйте скрипт для применения миграции с автоматическим созданием SSH туннеля:

```bash
python scripts/run_migration.py
```

Скрипт автоматически:
- Создаст SSH туннель к серверу (если нужно)
- Применит все неприменённые миграции, включая очистку данных
- Закроет туннель после завершения

### Способ 2: Через Alembic напрямую

```bash
# Убедитесь, что SSH туннель создан (если нужно)
# Затем выполните:
alembic upgrade head
```

### Способ 3: Через SQL напрямую на сервере

Если у вас есть прямой доступ к серверу:

```bash
# Подключитесь к серверу
ssh root@91.222.237.94

# Подключитесь к PostgreSQL
sudo -u postgres psql -d silent_couple_bot

# Выполните команды очистки:
TRUNCATE TABLE daily_state CASCADE;
TRUNCATE TABLE subscriptions CASCADE;
TRUNCATE TABLE lifetime_pair_history CASCADE;
TRUNCATE TABLE pair_demo CASCADE;
TRUNCATE TABLE pairs CASCADE;
TRUNCATE TABLE bot_messages CASCADE;
TRUNCATE TABLE users CASCADE;

# Сбросьте последовательности:
ALTER SEQUENCE users_id_seq RESTART WITH 1;
ALTER SEQUENCE pairs_id_seq RESTART WITH 1;
ALTER SEQUENCE subscriptions_id_seq RESTART WITH 1;
ALTER SEQUENCE lifetime_pair_history_id_seq RESTART WITH 1;
ALTER SEQUENCE bot_messages_id_seq RESTART WITH 1;

# Выйдите из psql:
\q
```

## Проверка после очистки

После применения миграции проверьте, что данные удалены:

```sql
-- Подсчет записей в таблицах (должно быть 0)
SELECT 
    'users' as table_name, COUNT(*) as count FROM users
UNION ALL
SELECT 'pairs', COUNT(*) FROM pairs
UNION ALL
SELECT 'subscriptions', COUNT(*) FROM subscriptions
UNION ALL
SELECT 'daily_state', COUNT(*) FROM daily_state
UNION ALL
SELECT 'pair_demo', COUNT(*) FROM pair_demo
UNION ALL
SELECT 'lifetime_pair_history', COUNT(*) FROM lifetime_pair_history
UNION ALL
SELECT 'bot_messages', COUNT(*) FROM bot_messages;
```

Все значения должны быть 0.

## Что делать после очистки

1. **Перезапустите бота** — чтобы он начал работать с пустой БД
2. **Перезапустите worker** — чтобы очистить кеш и состояние
3. **Очистите Redis** (опционально):
   ```bash
   redis-cli FLUSHALL
   ```
4. **Проверьте работу** — создайте тестовую пару через `/start`

## Откат миграции

**ВНИМАНИЕ:** Откат этой миграции невозможен, так как данные были удалены безвозвратно.

Если нужно откатить миграцию (удалить её из истории), можно использовать:

```bash
alembic downgrade -1
```

Но это только удалит миграцию из истории Alembic, данные не восстановятся.

## Безопасность

- ✅ Миграция использует `TRUNCATE` вместо `DELETE` — быстрее и эффективнее
- ✅ Используется `CASCADE` для автоматической очистки зависимых данных
- ✅ Последовательности сбрасываются для чистого старта
- ⚠️ Операция необратима — убедитесь, что у вас есть резервная копия, если нужна

## Резервная копия (рекомендуется)

Перед очисткой рекомендуется создать резервную копию:

```bash
# На сервере
pg_dump -U postgres -d silent_couple_bot > backup_before_clear_$(date +%Y%m%d_%H%M%S).sql

# Или через SSH туннель локально
pg_dump -h localhost -p 5433 -U postgres -d silent_couple_bot > backup_before_clear_$(date +%Y%m%d_%H%M%S).sql
```

## Часто задаваемые вопросы

### В: Можно ли восстановить данные после очистки?

**О:** Нет, операция необратима. Данные удаляются безвозвратно. Единственный способ восстановления — из резервной копии.

### В: Нужно ли останавливать бота перед очисткой?

**О:** Рекомендуется остановить бота и worker перед очисткой, чтобы избежать конфликтов.

### В: Что произойдет с текущими пользователями?

**О:** Все пользователи будут удалены. После очистки бот начнет работать с пустой БД, как будто он только что был установлен.

### В: Нужно ли очищать Redis?

**О:** Рекомендуется очистить Redis после очистки БД, чтобы удалить кешированные данные и состояния FSM.

### В: Можно ли очистить только часть данных?

**О:** Да, можно модифицировать миграцию или выполнить SQL команды вручную для очистки только нужных таблиц.
