# Silent Couple Bot 3.0 — Полное описание проекта

> Актуализировано по коду, состояние на октябрь 2026.
> Ежедневный ритуал «Доброе утро» / «Спокойной ночи» для двух близких людей.

## 1. Концепция продукта

Цель: каждый день дважды предлагать паре обменяться картинкой «Доброе утро» / «Спокойной ночи» — простой знак внимания «я помню о тебе» и сигнал «у меня всё в порядке».

Уникальность:

- **Минимализм** — нет аналитики, нет истории переписки, только сегодняшний день.
- **Никаких слов** — бот всё делает сам: нажал кнопку → партнёр получил открытку.
- **Защита от повторного демо** — повторно демо для той же связки пользователей получить нельзя (только через сброс администратором).
- **Оплата любым** — после успешного платежа подписка активируется сразу у всей пары, оба получают уведомление.
- **Честные окна по местному времени** — у каждого своя таймзона (синхронизация с телефоном через Mini App).

## 2. Технологический стек (фактический)

| Слой | Инструмент | Назначение |
|---|---|---|
| Bot core | Python 3.11, aiogram 3 | Обновления из Telegram забираются long polling'ом (входящие вебхуки Telegram не используются; исходящий прокси — `TELEGRAM_PROXY_URL`) |
| Background | arq (Redis) | `morning_sender` и `evening_sender` — каждую минуту (внутри фильтрация по персональным окнам); `dunning_notifications` и `send_renewal_reminders` — ежечасно; `cleanup_old_data` — 03:00 UTC; `cleanup_old_messages` — ежечасно :30; `send_share_nudge` — 14:00 UTC |
| Webhook-сервер / Mini App | FastAPI | Вебхук Robokassa, страница синхронизации таймзоны `/tz-sync`, `/health`; проверка подписи Telegram initData (HMAC-SHA256) |
| БД | PostgreSQL 15, SQLAlchemy 2.0 (async), asyncpg | 12 таблиц |
| Migrations | Alembic | |
| Cache/Queue | Redis 7 | Очередь arq, rate-limit, FSM-хранилище, отложенные доставки, дедупликация уведомлений, circuit breaker |
| Логи | structlog | JSON: stdout + ротируемый файл `logs/bot.log` |
| Мониторинг | Prometheus + Grafana | План (prometheus-client в зависимостях, но не подключён); сейчас — `/health`, внешние healthcheck-скрипты с Telegram-алертом |
| CI | GitHub Actions | pytest + проверка форматирования (black, isort) |
| Object Storage | не используется | MinIO удалён из проекта: картинки хранятся как Telegram file_id в таблице `pics_pool` |

## 3. Архитектура (high-level)

```
Telegram Users
   ↓
aiogram 3 (long polling через прокси, если задан)
   ├─ Bot-процесс (handlers → use_cases → application services → domain services → repositories)
   ├─ Webhook-сервер FastAPI (вебхук Robokassa, Mini App, /health; за nginx на сервере)
   └─ arq Worker (cron-задачи; защита от параллельного запуска через Redis-локи)
   ↓
PostgreSQL (12 таблиц) + Redis 7
```

Деплой — systemd-сервисы на VPS (`deploy/webhook.service`, `deploy/worker.service`) либо Docker (`docker-compose.prod.yml`).

## 5. База данных (12 таблиц)

| Таблица | Назначение |
|---|---|
| `users` | tg_id, username, consent, timezone_name (IANA), utc_offset, morning/evening_window_start_hour, preferred_mode |
| `consent_audit` | Факт согласия (IP + дата) для 152-ФЗ/GDPR |
| `pairs` | uid_a, uid_b, mode (silent/chat), status (trial/active/past_due/cancelled), nickname_a/b, delivery_chat (bot_dm/pair_dm) |
| `daily_state` | Только текущий день: morning/evening initiator, file_id, sent_at, responded_at; хранится 31 день (чистка в 03:00 UTC) |
| `subscriptions` | Пара, payer_id, period_end, is_lifetime, status (в т.ч. refunded) |
| `pair_payments` | История платежей (payer_id, inv_id, сумма) |
| `bot_messages` | Журнал сообщений бота; сами сообщения удаляются из Telegram через 48 ч (задача ежечасно) |
| `pair_demo` / `pair_demo_hash` | Блок-лист повторного демо: sha256-хеш связки «минимальный tg_id : максимальный tg_id» с солью; `pair_demo` — legacy, автоматически мигрируется в хеш-таблицу |
| `pair_first_payment_bonus_hash` | Блок повторного получения бонуса за первую оплату (тот же принцип хеша) |
| `lifetime_pair_history` | Позволяет воссоздать lifetime-пару после разрыва без нового демо |
| `pics_pool` | Пул картинок (Telegram file_id, тип morning/evening) |

## 6. Меню бота

| Команда | Что делает |
|---|---|
| `/start` | Онбординг/перезапуск: синхронизация таймзоны через Mini App → приветствие с принятием соглашения («✅ Принять и начать») → выбор режима → окно уведомлений (или инвайт-ссылка) |
| `/create_pair` | «➕ Создать дополнительную пару» |
| `/subscription` | Статус подписки |
| `/pay` | Тарифы и оплата (RUB/USD/EUR/KZT) |
| `/settings` | Режим, никнейм, окно уведомлений |
| `/share` | «📤 Поделиться ботом» |
| `/feedback` | Обратная связь |
| `/bot_info` | Информация + кнопка «ℹ️ Информация» (юрдоки: 24policybot.ru/legal) |
| `/delete` | Удаление всех данных (GDPR); блок-хеши демо/бонуса сохраняются |
| `/link` | Устарела: отвечает, что не требуется (доставка настраивается автоматически) |

Админ-команды (только для `ADMIN_TG_ID`): `/admin`, `/admin_stats`, `/admin_reset_demo` (сброс демо), `/admin_gift` (подарить подписку), `/admin_broadcast` (рассылка), `/cancel`.

## 7. Сценарии взаимодействия

### 7.1 Silent Mode (по умолчанию)

- В персональное 1-часовое окно (по умолчанию утро 07:00–08:00, вечер 21:00–22:00 по местному времени пользователя) бот присылает промпт: «🌅 Утро! Кому отправить пожелание? Выберите партнёра:» с кнопками «📨 {партнёр}».
- Первый, кто нажал, — инициатор: кнопка в промпте меняется на «✅ {партнёр} — отправлено», отправителю приходит подтверждение «✅ Пожелание доставлено…».
- Партнёр получает случайную картинку из пула с подписью «от {никнейм}. Со мной всё в порядке ❤️» (утро) / «…спокойной ночи ❤️» (вечер) и кнопкой «Отправить в ответ».
- Ответ — тоже случайная ответная картинка инициатору; кнопка с картинки убирается, цикл закрыт. Данные дня пишутся в `daily_state`.
- Если получатель молчит: напоминания «Тебя ждут ❤️» через 3/6/9 часов; инициатору с 10-го часа — «⚠️ {ник} не отвечает…» каждые 6 часов (можно отменить).
- Если получателю ещё «не время» (его окно не наступило) — желание откладывается в Redis (TTL 48 ч) и доставляется, когда у него начнётся окно. Желание аннулируется с наступлением противоположного периода (утро гасится вечером и наоборот).
- Если у пары подписка истекла (past_due) — вместо кнопки отправления приходит «💳 демо закончилось, оплатить».

### 7.2 Chat Mode

- Тот же ритуал «кто первый», но подписи к картинкам выбираются случайно из нейтральных пулов (15 утренних / 15 вечерних вариантов).
- Исторически задумывалась доставка в общий чат пары (`delivery_chat = pair_dm`, команда `/link`), но сейчас реально работает доставка в личный чат с ботом (bot_dm); команда `/link` устарела и ничего не делает.
- Переключение режима — в `/settings`.
- Mini App используется для синхронизации таймзоны (страница `/tz-sync` читает таймзону телефона), health-проверок и отправки отдельной картинки через `/send`.

## 8. Оплата и статус

- Провайдер — **Robokassa** (прямые платёжные ссылки, MD5-подпись, вебхук ResultURL, circuit breaker на Redis). YooKassa отключена и осталась только в закомментированном legacy.
- Тарифы (RUB, базовые):

  | Тариф | Цена |
  |---|---|
  | 1 месяц | 299 ₽ |
  | 3 месяца | 799 ₽ |
  | 6 месяцев | 1399 ₽ |
  | 1 год | 2499 ₽ |
  | Навсегда | 4999 ₽ |

- Иные валюты (USD/EUR/KZT) считаются автоматически: базовая цена × курс ЦБ РФ (живой курс, кэш 30 мин) × маржа 17%. Оплата доступна в 4 валютах.
- Бонус за первую оплату пары: **+30 дней** («1 месяц → 2 месяца 🎁»); повторно не выдаётся (хеш-блок-лист).
- Платит любой из пары: вебхук активирует подписку всей пары (payer_id — только книжный учёт), сбрасывает просрочку и уведомляет обоих.
- Напоминания: о продлении — за 3 дня до конца, повтор каждые 6 часов (обоим); о просрочке — пара переводится в past_due ежечасной задачей, уведомление не чаще раза в сутки, плюс первые 3 дня ежедневно и далее раз в 7 дней в утренних/вечерних рассылках.

## 9. Флоу «кто первый» (без истории)

Хранится только сегодняшний день (`daily_state`): morning/evening initiator, file_id, sent_at, responded_at. Строки старше 31 дня удаляются ежедневной задачей (03:00 UTC); `bot_messages` (для автоудаления отправленных сообщений) — через 48 часов (ежечасно).

## 10. Защита от повторного демо

- При создании пары создаётся триал на 7 дней (`TRIAL_PERIOD_DAYS`, настраивается) и записывается хеш связки: sha256("min_tg_id:max_tg_id" + соль) → `pair_demo_hash`.
- Повторное создание пары из тех же двух аккаунтов демо не получает: либо отказ («Демо период для этой связи уже был использован»), либо сразу past_due с требованием оплаты.
- Хеш **связки**, а не глобальный блок пользователя: те же люди с другими партнёрами могут пройти демо.
- Сброс только администратором (`/admin_reset_demo`): хеш удаляется, при следующем /start DemoRestoreFlow возвращает паре триал и уведомляет обоих («✅ Демо режим восстановлен!»).
- Аналогичный хеш-блок существует для бонуса +30 дней за первую оплату.

## 11. Масштабирование (текущая реальность и запас)

Сейчас: один VPS, systemd (webhook-сервер + arq worker), PostgreSQL и Redis на сервере. Этого достаточно для текущих объёмов.

Заложено в архитектуру: stateless-процессы, Redis-локи от дублей cron, DAL/репозитории, DI на протоколах.

Ограничение: long polling не масштабируется на несколько реплик бота — для горизонтального масштабирования нужен переход на входящие вебхуки и/или очередь обновлений; мониторинг (Prometheus/Grafana) пока не подключён. Это направления роста, а не работающий функционал.

## 12. Мониторинг и алерты (факт)

- `/health` на webhook-сервере и в Mini App (статус инициализации бота).
- Контейнерные healthchecks: бот — доступность Telegram API (с учётом прокси), worker — Redis PING.
- Внешний healthcheck-скрипт (`deploy/healthcheck.sh`, cron каждые 2 минуты): проверка процесса, автоперезапуск, Telegram-алерт админу.
- Логи: structlog JSON (stdout + `logs/bot.log` с ротацией 10 МБ × 5).
- Prometheus + Grafana + Loki — план (не подключено).

## 13. Юридика (152-ФЗ + GDPR)

- **Локализация** — VPS в РФ.
- **Согласие** — inline-кнопка при онбординге, факт фиксируется в `consent_audit` (IP + дата).
- **Удаление** — `/delete`: каскадное удаление данных пары; хеши демо/бонуса сохраняются (защита от повторного демо).
- **Документы** — кнопка «ℹ️ Информация» на экранах оплаты и в `/bot_info` ведёт на 24policybot.ru/legal (оферта, политика).
- **Платёжный провайдер** — Robokassa.

## 14. Роадмап

Реализовано и в проде: 2 режима, персональные окна и таймзоны, никнеймы, Robokassa с 4 валютами и живым курсом, бонус за первую оплату, напоминания всех типов, админ-панель, защита демо, GDPR-удаление, CI.

Планы: голосовые пожелания (ogg), загрузка пользовательских картинок, AI-генерация изображений, подключение Prometheus/Grafana, горизонтальное масштабирование бота.

Вырезано/не используется: сюрприз-картинки (1 из 4) — код удалён из основного флоу; еженедельная сводка — задача отключена.
