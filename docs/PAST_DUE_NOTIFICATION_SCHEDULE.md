# Расписание уведомлений после окончания демо периода

## Новая логика отправки уведомлений

После окончания демо периода пары получают уведомления о необходимости оплаты по следующему расписанию:

### Первые 3 дня после окончания демо
- **Частота**: Каждое утро (один раз в день)
- **Время**: В утреннем окне (07:00-08:00 по местному времени пользователя)
- **Цель**: Напоминать пользователям о необходимости оплаты в первые дни

### После 3 дней
- **Частота**: Раз в 7 дней (только утром)
- **Время**: В утреннем окне (07:00-08:00 по местному времени пользователя)
- **Цель**: Не надоедать пользователям частыми напоминаниями, но периодически напоминать о возможности оплаты

### Вечерние уведомления
- **Отключены**: Уведомления о просрочке отправляются только утром, вечером не отправляются

## Техническая реализация

### Логика в `morning_sender`

1. **Получение подписки**: Для каждой пары со статусом `past_due` получаем подписку
2. **Вычисление дней**: `days_since_expiry = (today - subscription.period_end).days`
3. **Проверка условий**:
   - Если `days_since_expiry <= 3`: проверяем, было ли уже отправлено сегодня (через Redis)
   - Если `days_since_expiry > 3`: проверяем, прошло ли 7 дней с последней отправки

### Хранение в Redis

**Первые 3 дня:**
- Ключ: `past_due_notification_morning:{pair_id}:{date}`
- TTL: 24 часа (автоматически удаляется в конце дня)

**После 3 дней:**
- Ключ: `past_due_last_notification:{pair_id}`
- Значение: Дата последней отправки (ISO формат)
- TTL: Нет (хранится до следующей отправки)

### Пример работы

```
День 0: Демо период закончился (period_end = 2024-01-01)
День 1: ✅ Отправлено утром (days_since_expiry = 1)
День 2: ✅ Отправлено утром (days_since_expiry = 2)
День 3: ✅ Отправлено утром (days_since_expiry = 3)
День 4: ❌ Пропущено (days_since_expiry = 4, но прошло только 1 день с последней отправки)
День 5: ❌ Пропущено
День 6: ❌ Пропущено
День 7: ❌ Пропущено
День 8: ❌ Пропущено
День 9: ❌ Пропущено
День 10: ✅ Отправлено утром (прошло 7 дней с последней отправки)
День 11-16: ❌ Пропущено
День 17: ✅ Отправлено утром (прошло 7 дней)
```

## Изменения в коде

### `src/worker/jobs.py`

1. **`morning_sender`** (строки 67-220):
   - Добавлена логика проверки дней с момента окончания демо
   - Первые 3 дня: отправка каждое утро
   - После 3 дней: отправка раз в 7 дней

2. **`evening_sender`** (строка 477):

## Преимущества

- ✅ **Меньше спама**: Пользователи не получают уведомления каждый день после 3 дней
- ✅ **Эффективность**: Первые 3 дня - активное напоминание, затем периодическое
- ✅ **Гибкость**: Легко изменить интервалы (3 дня / 7 дней) в коде
- ✅ **Отказоустойчивость**: Если Redis недоступен, уведомления все равно отправляются
