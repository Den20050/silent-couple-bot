1. Структура проекта и организация кода
Принято:
Copy
src/
  bot/          # handlers, middlewares, filters
  worker/       # arq cron jobs (morning, evening, cleanup, dunning)
  mini_app/     # FastAPI routes + static
  db/           # SQLAlchemy models, **repositories (DAL)**, Alembic
  services/     # business logic (image, payment, telegram)
  core/         # pydantic-settings, constants, logger
Решения:
Repository-pattern (тонкий DAL) — да:
repos/daily_state.py, repos/user_demo.py, repos/subscription.py
Плюсы: тестируемость, единое место SQL, скрываем ORM от handlers.
Unit of Work — нет, транзакции ведёт FastAPI-сервис или arq-job.
Слой services вызывает репозитории, не вызывает SQLAlchemy напрямую.

3. Оплата и статусы
3.1 Логика «один платит → оба active»
Webhook YooKassa → успех →
UPDATE pairs SET status='active', period_end=now()+30d WHERE id=$pair_id
+ notify both users «✅ Подписка активна до …»
3.2 Повторные платежи
Продлеваем period_end (не создаём новую строку)
Idempotency-key в YooKassa → защита от дублей
3.3 Trial
Да, 7 дней без карты (по умолчанию pairs.status='trial')
По истечении cron переводит в past_due и шлёт /pay кнопку
4. Режимы работы
4.1 Выбор режима
При /start — inline-кнопки:
[💬 Часто общаемся] → mode='chat'
[💔 Редко] → mode='silent'
Поменять потом — нельзя (минимализм)
4.2 Chat Mode / common_chat_id
Только через команду /link (бот должен увидеть себя в чате)
Автоматически не определяем (меньше прав, меньше кода)
5. Расписание и часовые пояса
5.1 Определение часового пояса
Автоматически по message.date (UTC) vs time() сервера → вычисляем offset
Команда /tz есть, но скрыта (используется редко)
5.2 Окно отправки
Random ±30 минут от центра:
07:30 ±30 мин → 07:00-08:00
21:30 ±30 мин → 21:00-22:00
Cron worker запускается каждые 30 мин → 2 окна покрыты
6. Картинки
6.1 Источник
Используем существующие morning/*.jpg, evening/*.jpg (500-1000 шт)
6.2 Загрузка в MinIO
Скрипт scripts/load_images.py → Telegram Upload → получаем file_id → сохраняем в pics_pool
6.3 Уникальность
Проверка по daily_state за 30 дней:
sql
Copy
SELECT DISTINCT morning_file_id
FROM daily_state
WHERE pair_id = $pair AND day > CURRENT_DATE - 30
Если картинок не осталось → сброс списка (начинаем сначала)

11. Безопасность
11.1 Rate-limiting
Cloudflare — 100 req/s/IP (WAF)
Bot middleware — 50 msg/s per user (Redis-backed)
11.2 Спам/флуд
1 сообщение в 2 секунды per user (храним в Redis TTL)
Ban на 1 час при >20 сообщений/мин
12. Обработка ошибок
12.1 Circuit breaker (YooKassa)
Да, как в 2.2: 3 ошибки за 60 сек → 60 сек open
Реализация: middlewares/circuit.py, храним в PostgreSQL
12.2 Telegram API retry
3 попытки, экспоненциальная задержка (1s, 2s, 4s)
Логируем и отправляем в dead-letter (arq позволяет)
