Silent Couple Bot 3.0 — Полное описание проекта
Минимализм + защита от повторного демо + масштаб 100 k+ пользователей
Без кода, только архитектура, сценарии и структура.
1. Концепция продукта
Цель: ежедневный обмен картинками «Доброе утро» / «Спокойной ночи» между двумя людьми.
Уникальность:
Минимализм — нет аналитики, нет лишних таблиц, нет истории переписки.
Защита от повторного демо — один запуск = оба пользователя в «вечном» блок-листе.
Оплата любым — после успеха статус «оплачено» появляется у обоих мгновенно.
Масштаб 100 k+ — stateless-сервисы, горизонтальное масштабирование без переписывания кода.

7. Сценарии взаимодействия
7.1 Silent Mode (по умолчанию)
A нажимает /start → демо 7 дней → A и B вносятся в user_demo
07:30 → бот шлёт обоим:
«Хотите отправить пожелание? [Отправить]»
A нажимает первым → оба сообщения редактируются:
A: «✅ Вы отправили пожелание»
B: «\u200B» (невидимый символ)
Бот отправляет B картинку + кнопку «Отправить в ответ»
B отвечает → цепочка закрыта, кнопки исчезают
Вечер — аналогично в 21:30
7.2 Chat Mode (через Mini App)
A выбирает «chat mode» → инструкция добавить бота в чат
/link → сохраняется common_chat_id
07:30 → бот шлёт обоим Web App кнопку:
Любой нажимает → открывается Mini App → «Отправить» → картинка в общем чате
История остаётся в личном чате пары, без переключения

9. Флоу «кто первый» (без истории)
Хранится только сегодняшний день (daily_state):
Python
Copy
UPDATE daily_state
SET morning_initiator = $uid, morning_file_id = $file
WHERE pair_id = $pair AND day = CURRENT_DATE
  AND morning_initiator IS NULL;
48 часа спустя строка удаляется → место освобождается.
10. Защита от повторного демо
Таблица user_demo (1 столбец):
sql
Copy
INSERT INTO user_demo(tg_id) VALUES ($uid_a),($uid_b)
ON CONFLICT DO NOTHING;
Первый запуск любого → оба id в таблице
Оплата любого → та же команда (дубль не вставится)
Удаление бота → id остаётся → повторного демо нет
